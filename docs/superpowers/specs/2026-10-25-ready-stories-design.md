# Готовые сюжеты и «Галерея готовых»

Дата: 2026-10-25. Источник идей: приложение Laixi (`~/Downloads/Laixi/Scripts`).

## Зачем

В Laixi есть готовые скрипты под TikTok, Spotify и автолистание. У фермы вся
инфраструктура уже есть (`humanize`, `loop`, `chance`, `phrase`, `budget`,
стражи), но нет готовых сюжетов: 2026-10-17 шаблоны прогрева убрали, потому
что они жили на тапах вслепую и не были проверены на телефонах. Эта работа
возвращает сюжеты иначе: цели с запасными вариантами, честная пометка
«не проверено», отдельная галерея вместо засорения списка «Мои».

## Что взято из Laixi

`tiktok.js` и `spotify.js` обфусцированы (`_0x…`): строки зашифрованы,
идентификаторы элементов TikTok/Spotify не извлекались. Поток управления
читается по числам и именам функций. Берутся только приёмы, код не копируется.
Источники: настройки и UI, `startMission`/`swipeVideo`/`changeSearchWord`/
`comment` из `tiktok.js` и читаемый `自动上滑脚本.js`:

- шансы лайка, комментария, избранного, подписки (по умолчанию 20/20/20/10%);
- пауза между видео случайная «от и до» (5–10 с, в автолистании 7–20 с);
- файл слов поиска и файл комментариев, по одной строке;
- смена слова поиска каждые N свайпов (N случайно от 3 до 5);
- число просмотров, 0 = без ограничения;
- Spotify: полный трек или диапазон секунд, шанс лайка;
- свайп вверх по кривой со случайными координатами.

## Приёмы из исходника TikTok (берём) и что делаем иначе

| Приём в Laixi | У нас |
|---|---|
| Бюджет времени на видео: целевая пауза `random(min,max)` минус время, уже потраченное на лайк/избранное/подписку/комментарий; остаток не меньше 1 с. Видео занимает заданное время, сколько бы действий ни сделали | Берём. `story.dwell_left(target, spent)` |
| Микро-паузы 1–3 с между действиями на одном видео | Берём: `ctx.pause()` между действиями |
| Порядок на видео: лайк → избранное → подписка → комментарий | Берём |
| Панель действий не найдена: только смотрит 5–7 с, действий нет | Берём: без панели действий нет, сюжет не падает |
| Свайп: старт x 500–800, y 1300–1600, финиш x 500–800, y 350–500 (экран 1080×2280), 1 с, после свайпа 2 с | Берём как доли экрана (≈0.46–0.74, 0.57–0.70 → 0.15–0.22), не пиксели: ферма работает на разных разрешениях |
| Смена слова поиска: не на первом видео, интервал 3–5 перегенерируется после каждой смены; слова по кругу по порядку | Берём интервал. Слова берём в случайном порядке без повтора подряд |
| Комментарии по кругу в одном порядке | **Иначе:** случайный выбор плюс `{а\|б}`. Один и тот же порядок на всех телефонах — признак автоматизации (см. `phrases.py`) |
| Пока не на главном экране — «Назад» с паузой 2 с | Берём: общий выход фермы `ctx` (`ESCAPE_STEPS`) и `watch=True` |
| Проверка формы до старта: min < max, сумма шансов > 0, шансы в 0–100 | Берём: `story.validate()` до запуска, понятное сообщение |
| Пауза/продолжить громкостью и плавающим окном | Не берём: у фермы есть отмена и «остановить с вопросом» |
| Шансы без потолка за сутки | **Иначе:** `ctx.budget` включён по умолчанию |
| Итог числом в плавающем окне | Журнал: `Tally.line()` |

## Объём

1. Модуль `backend/farm/story.py` — чистая логика без adb.
2. Четыре сюжета-файла в `backend/scenarios/gallery/`.
3. Галерея готовых: API `/api/gallery` и вкладка «Готовые» в разделе «Сценарии».
4. Профили поведения, загрузка `.txt` со словами и фразами, живая сводка в журнале.

Вне объёма: деобфускация Laixi, запуск Autox.js на телефонах, новые виды шагов
конструктора.

## 1. `backend/farm/story.py`

Чистый модуль, как `phrases.py` и `ui/tree.py` (см. `docs/GOTCHAS.md`): ни adb,
ни диска, ни FastAPI. Все функции принимают `rng` для воспроизводимых тестов.

- `Profile` — профиль поведения: `quiet`, `normal`, `active`. Содержит шансы
  `like`, `comment`, `favorite`, `follow`, паузу `(lo, hi)` и смену слова
  `(lo, hi)` в свайпах. Таблица `PROFILES` — единственное место с числами.
- `resolve_profile(name, overrides)` — профиль плюс явные значения из формы
  запуска. Явное значение побеждает профиль. Неизвестное имя даёт `normal`.
- `parse_lines(text, limit)` — текст файла в список: обрезка пробелов, пустые
  строки и дубликаты выброшены, не больше `limit` строк. Не падает на мусоре.
- `WordRotator(words, every, rng)` — `current()` и `tick()`. После N тиков
  берёт следующее слово, N случайно из `every`. Пустой список даёт `None`, не
  ошибку.
- `pick_actions(profile, rng)` — какие действия сделать на этом видео:
  подмножество `{like, comment, favorite, follow}`, каждое независимо по шансу.
- `dwell_left(target, spent)` — сколько ещё ждать на видео: `max(1, target - spent)`.
- `validate(params)` — список понятных ошибок формы (min < max, сумма шансов
  больше нуля, шансы от 0 до 100); пустой список означает «можно запускать».
- `Tally` — счётчик просмотров и действий. `line()` даёт строку журнала:
  «просмотров 14, лайков 3, комментариев 1, подписок 0».

Профили (стартовые, правятся в одном месте):

| | like | comment | favorite | follow | пауза, с |
|---|---|---|---|---|---|
| quiet | 10 | 3 | 5 | 2 | 8–18 |
| normal | 20 | 8 | 10 | 5 | 6–14 |
| active | 30 | 15 | 15 | 10 | 5–10 |

Эти значения консервативнее Laixi (20/20/20/10). Причина: комментарии и подписки
на десятках аккаунтов первыми приводят к блокировке.

## 2. Сюжеты

Файлы лежат в `backend/scenarios/gallery/<ключ>.py`. Формат тот же, что у
остальных сценариев: `NAME`, `DESCRIPTION`, `PARAMS`, `run(ctx)`. Дополнительные
поля для галереи:

```python
GALLERY = {
    "platform": "TikTok",          # подпись и фильтр
    "verified": False,             # «проверено на телефоне»
    "package": "com.zhiliaoapp.musically",
}
```

Общие правила для всех сюжетов:

- `ctx.watch_popups()`, `ctx.humanize()`, `ctx.unlock()` в начале;
- каждое нажатие через `ctx.click_target(...)`: `resourceId`, затем текст, затем
  иконка, координаты только последним запасным вариантом;
- действия, которые меняют аккаунт (лайк, комментарий, избранное, подписка),
  идут через `ctx.budget(...)` с потолком за сутки, по умолчанию включённым;
- `ctx.loop(..., watch=True)` ловит зависание и уход из приложения;
- в конце каждого круга `ctx.log(tally.line())` раз в 5 кругов;
- шаг, не нашедший цель, не роняет сюжет молча: остановка с вопросом идёт
  штатным механизмом фермы.

Сюжеты:

| Ключ | Что делает | Параметры |
|---|---|---|
| `tiktok_feed` | Лента-прогрев: листает, ставит лайк, пишет комментарий из списка, добавляет в избранное, подписывается; меняет слово поиска | профиль, просмотров, слова, фразы, потолки |
| `shorts_autoscroll` | Автолистание любых шортсов (TikTok, YouTube Shorts, Reels): свайп по кривой, пауза, без действий | пакет, просмотров, пауза от и до |
| `spotify_listener` | Ищет слово, запускает трек, слушает целиком или диапазон секунд, ставит лайк | слова, режим прослушивания, диапазон, шанс лайка |
| `vk_feed` | Лента VK: листает, лайкает по шансу | профиль, кругов, потолок лайков |
| `telegram_channels` | Читает каналы: открывает, листает, возвращается; без публикаций | список каналов, кругов, пауза |
| `youtube_shorts` | YouTube Shorts: смотрит, лайкает по шансу | профиль, просмотров, потолок лайков |

Если у телефона нет приложения, `ensure_app` (шаг «Приложение готово») останавливает
сюжет с понятным сообщением, а не вызывает тап вслепую.

## 3. Галерея готовых

**API** (`backend/farm/api/gallery.py`, тонкий слой над `farm/gallery.py`):

- `GET /api/gallery` — список карточек: ключ, название, описание, платформа,
  `verified`, `added` (уже скопирован в «Мои»).
- `POST /api/gallery/{key}/add` — копирует файл в `backend/scenarios/`.
  Имя берётся из тела запроса (необязательно); при совпадении имени
  добавляется суффикс `_2`. Ответ: ключ созданного сценария. Исходник в
  `gallery/` не меняется.

`farm/gallery.py` — читает `backend/scenarios/gallery/`, импортируя только
метаданные (по тому же пути, что `scenarios._load_file`). Файлы из `gallery/` не
попадают в `scenarios.discover()`, поэтому в «Мои» и в запуск не попадают, пока
их не добавили.

**Интерфейс.** В разделе «Сценарии» вкладка «Готовые»: карточка с названием,
платформой, описанием, значком «Не проверено на телефоне» (до тех пор, пока
`verified = False`) и кнопкой «Добавить в мои». После добавления карточка
показывает «Уже в моих» и ссылку на сценарий. Все тексты — в
`frontend/strings/ru.json`. Правила — из `farm-ux`: простой язык, без жаргона,
пустое состояние объясняет, что делать.

## 4. Профили, файлы слов, сводка

- **Профиль:** параметр `profile` (select) в каждом сюжете с действиями. Ручные
  поля (шансы, паузы) переопределяют профиль.
- **Слова и фразы:** параметры типа текст с несколькими строками. Строки
  разбирает `story.parse_lines`, фразы дальше размножает `ctx.phrase`
  (`{привет|здравствуй}`). Загрузка `.txt` — через существующую загрузку файлов
  в форме запуска; если её для параметров нет, в первом шаге остаётся
  многострочное поле.
- **Сводка:** `Tally.line()` в журнале каждые 5 кругов и в конце.

## Ошибки и устойчивость

- Пустой список слов: сюжет листает ленту без поиска, пишет об этом в журнал.
- Пустой список комментариев: комментарии отключены, остальные действия работают.
- Потолок исчерпан (`BudgetReached`): сюжет заканчивается успешно с сообщением,
  как и остальные сценарии с потолком.
- Цель не найдена: штатная остановка и вопрос фермы, не молчаливый пропуск.
- Файл галереи не читается или битый: карточка пропущена, в журнал сервера
  уходит предупреждение; остальные карточки видны.

## Тесты

Телефоны не нужны, как и у остальных 850+ тестов:

- `test_story.py`: профили и переопределения, `parse_lines` (пустое, дубли,
  лимит), `WordRotator` (смена через N, пустой список), `pick_actions` с
  фиксированным `rng`, `Tally.line`.
- `test_gallery.py`: список карточек, добавление, коллизия имён, исходник не
  изменён, битый файл не ломает список, файлы галереи не попадают в `discover()`.
- `test_gallery_scenarios.py`: каждый сюжет импортируется, имеет `NAME`,
  `PARAMS`, `GALLERY` и функцию `run`; параметры по умолчанию проходят
  `resolve_params`.
- JS-тест карточки галереи по образцу существующих `test_*_js.py`.

## Что проверить на живом телефоне (после слияния)

Селекторы приложений записаны по известным `resourceId` и текстам и могут
отличаться в версии на вашем парке. Пока сюжет не прогнали на реальном
телефоне, у него стоит `verified = False`, и галерея это показывает. После
проверки владелец меняет флаг одной строкой.
