# Готовые сюжеты и «Галерея готовых»

Дата: 2026-10-25. Источник идей: приложение Laixi (`~/Downloads/Laixi/Scripts`).

## Зачем

В Laixi есть готовые скрипты под TikTok, Spotify и автолистание. У фермы вся
инфраструктура уже есть (`humanize`, `loop`, `chance`, `phrase`, `budget`,
стражи), но нет готовых сюжетов: 2026-10-17 шаблоны прогрева убрали, потому
что они жили на тапах вслепую и не были проверены на телефонах. Эта работа
возвращает сюжеты иначе: цели с запасными вариантами, честная пометка
«не проверено», отдельная галерея вместо засорения списка «Мои».

## Что взято из Laixi

`tiktok.js` и `spotify.js` обфусцированы (`_0x…`). По просьбе владельца файлов
строки расшифрованы (RC4 и base64 из самих файлов, в изолированном vm без
доступа к системе), а потом прочитана логика. Проверка на сетевые вызовы,
оболочку, доступ к контактам и файлам вне выбора слов: ничего нет. Единственная
связь с хостом — `sendBroadcast` со счётчиком просмотров приложению Laixi.
Берутся приёмы и идентификаторы экранов, код не копируется. Источники:
`tiktok.js`, `spotify.js` и читаемый `自动上滑脚本.js`:

- шансы лайка, комментария, избранного, подписки (по умолчанию 20/20/20/10%);
- пауза между видео случайная «от и до» (5–10 с, в автолистании 7–20 с);
- файл слов поиска и файл комментариев, по одной строке;
- смена слова поиска каждые N свайпов (N случайно от 3 до 5);
- число просмотров, 0 = без ограничения;
- Spotify: полный трек или диапазон секунд, шанс лайка;
- свайп вверх по кривой со случайными координатами.

## Приёмы из исходника TikTok (берём) и что делаем иначе

| Приём в Laixi | У нас |
|---|---|
| Бюджет времени на видео: целевая пауза `random(min,max)` минус время, уже потраченное на лайк/избранное/подписку/комментарий; остаток не меньше 1 с. Видео занимает заданное время, сколько бы действий ни сделали | Берём. `story.dwell_left(target, spent)` |
| Микро-паузы 1–3 с между действиями на одном видео | Берём: `ctx.pause()` между действиями |
| Порядок на видео: лайк → избранное → подписка → комментарий | Берём |
| Панель действий не найдена: только смотрит 5–7 с, действий нет | Берём: без панели действий нет, сюжет не падает |
| Свайп: старт x 500–800, y 1300–1600, финиш x 500–800, y 350–500 (экран 1080×2280), 1 с, после свайпа 2 с | Берём как доли экрана (≈0.46–0.74, 0.57–0.70 → 0.15–0.22), не пиксели: ферма работает на разных разрешениях |
| Смена слова поиска: не на первом видео, интервал 3–5 перегенерируется после каждой смены; слова по кругу по порядку | Берём интервал. Слова берём в случайном порядке без повтора подряд |
| Комментарии по кругу в одном порядке | **Иначе:** случайный выбор плюс `{а\|б}`. Один и тот же порядок на всех телефонах — признак автоматизации (см. `phrases.py`) |
| Пока не на главном экране — «Назад» с паузой 2 с | Берём: общий выход фермы `ctx` (`ESCAPE_STEPS`) и `watch=True` |
| Проверка формы до старта: min < max, сумма шансов > 0, шансы в 0–100 | Берём: `story.validate()` до запуска, понятное сообщение |
| Пауза/продолжить громкостью и плавающим окном | Не берём: у фермы есть отмена и «остановить с вопросом» |
| Шансы без потолка за сутки | **Иначе:** `ctx.budget` включён по умолчанию |
| Итог числом в плавающем окне | Журнал: `Tally.line()` |

## Что внутри скриптов Laixi (по расшифровке)

Хост-функции `random`, `rs`, `cvr`, `tips` в файлах не определены: их даёт
рабочая среда Laixi (Autox.js), в нашей ферме их заменяют `ctx.chance`,
`ctx.pause`, `ctx.click_target`, `story.validate`.

### TikTok (`com.zhiliaoapp.musically`, версия скрипта ver520)

Цели в скрипте ищутся по **структуре экрана**, а не по `resourceId`: id
у TikTok меняются между версиями, структура держится дольше.

| Что | Как находит Laixi | Как берём мы |
|---|---|---|
| Запуск | `startActivity` с `com.ss.android.ugc.aweme.main.MainActivity` | `ctx.launch_app` + `ctx.wait_app` |
| Нижняя панель | `LinearLayout` на y≈2200–2250 (≈0.96–0.99 высоты) с 5 детьми; 0-й — «Главная» | структурный селектор + запасной тап по доле экрана |
| Колонка действий справа | `LinearLayout` с ≥5 детьми. Дети: 0 → аватар (его `child(0).child(1)` — «+» подписки, если `clickable`), 1 — лайк, 2 — комментарий, 3 — избранное (только если детей >5), 4 — поделиться | то же через `click_target(sel=…)`; индексы вынесены в константы сюжета |
| Поиск | иконка по координатам (996,171) ≈ (0.92, 0.075); поле — `EditText`; кнопка — текст «Search» до 5 попыток, затем тап по полю; фильтр — текст «Unwatched»; плитка — кликабельный `FrameLayout` с >1 детьми, у 2-го ребёнка есть дети, **случайная** из найденных | то же; плитка выбирается случайно |
| Не на ленте | `SearchResultActivity` или не `MainActivity`/`FrameLayout` → пауза 2 с и «Назад» по кругу | `ctx.back()` в цикле до N раз, затем падение с вопросом фермы |
| Комментарий | тап по иконке → 1–3 прокрутки с паузами 1–3 с («читает») → ввод в `EditText` (editable) → отправка = **последний** ребёнок родителя поля → тап (996,171) закрывает панель | то же; текст идёт через `ctx.phrase`, ввод через `ctx.type` |
| Свайп ленты | старт x 500–800, y 1300–1600 → финиш x 500–800, y 350–500 при экране 1080×2280, длительность 1 с, затем 2 с | доли экрана `(0.46–0.74, 0.57–0.70) → (0.46–0.74, 0.15–0.22)` через `ctx.swipe` |

Шанс каждого действия — независимый бросок на видео. Подписка требует, чтобы
элемент «+» нашёлся и был кликабелен, иначе молча пропускается.

### Spotify (`com.spotify.music`)

Здесь скрипт опирается на `resourceId` (они стабильнее, чем в TikTok):

| Что | `resourceId` |
|---|---|
| Вкладка поиска | `com.spotify.music:id/search_tab` |
| Поле-кнопка поиска | `com.spotify.music:id/find_search_field` |
| Строка запроса | `com.spotify.music:id/query` |
| Признак «результаты есть» | `com.spotify.music:id/search_body` |
| Строка результата и её «⋯» | `…:id/row_root`, `…:id/context_menu_button` |
| Лайк | `…:id/add_to_button`; если открылся `com.spotify.tome.pageactivity.PageActivity` — «Назад» |
| Название трека | `…:id/track_info_view_title` |
| Обложка (открыть плеер) | `…:id/cover_image` |
| Полоса перемотки | `…:id/seekbar`, класс `android.widget.SeekBar` |

Сценарий: поиск слова → пауза 2–5 с → тап по первому результату **левее
кнопки «⋯»** на 200 пикселей (чтобы не попасть в меню) → пауза 1–3 с → лайк по
шансу → прослушивание.

- **Целиком:** опрос названия трека раз в 2 с, пока оно не сменится.
- **Диапазон секунд:** открыть плеер по обложке; с шансом 40% перематывать —
  серией свайпов по полосе в случайные точки, пока набранное время не дойдёт до
  случайной цели из диапазона, длина шага `min…max−1` секунд, последний шаг
  обрезается до остатка; иначе просто ждать цель; затем «Назад».

В `story.py` для этого добавляется `seek_plan(total, lo, hi, rng)` — список
пауз, сумма которых ровно `total`.

Выводы для сюжетов: структурные индексы и `resourceId` из этого раздела идут
**первым** вариантом в цепочке `click_target`, остальные способы (текст, иконка,
доли экрана) — запасными. Они работали в версии приложений, под которую написан
скрипт, поэтому сюжеты всё равно ставятся с `verified = False`, пока их не
прогнали на вашем парке.

## Объём

1. Модуль `backend/farm/story.py` — чистая логика без adb.
2. Четыре сюжета-файла в `backend/scenarios/gallery/`.
3. Галерея готовых: API `/api/gallery` и вкладка «Готовые» в разделе «Сценарии».
4. Профили поведения, загрузка `.txt` со словами и фразами, живая сводка в журнале.

Вне объёма: деобфускация Laixi, запуск Autox.js на телефонах, новые виды шагов
конструктора.

## 1. `backend/farm/story.py`

Чистый модуль, как `phrases.py` и `ui/tree.py` (см. `docs/GOTCHAS.md`): ни adb,
ни диска, ни FastAPI. Все функции принимают `rng` для воспроизводимых тестов.

- `Profile` — профиль поведения: `quiet`, `normal`, `active`. Содержит шансы
  `like`, `comment`, `favorite`, `follow`, паузу `(lo, hi)` и смену слова
  `(lo, hi)` в свайпах. Таблица `PROFILES` — единственное место с числами.
- `resolve_profile(name, overrides)` — профиль плюс явные значения из формы
  запуска. Явное значение побеждает профиль. Неизвестное имя даёт `normal`.
- `parse_lines(text, limit)` — текст файла в список: обрезка пробелов, пустые
  строки и дубликаты выброшены, не больше `limit` строк. Не падает на мусоре.
- `WordRotator(words, every, rng)` — `current()` и `tick()`. После N тиков
  берёт следующее слово, N случайно из `every`. Пустой список даёт `None`, не
  ошибку.
- `pick_actions(profile, rng)` — какие действия сделать на этом видео:
  подмножество `{like, comment, favorite, follow}`, каждое независимо по шансу.
- `dwell_left(target, spent)` — сколько ещё ждать на видео: `max(1, target - spent)`.
- `seek_plan(total, lo, hi, rng)` — разбивает цель прослушивания на паузы между
  перемотками; сумма равна `total`, последний шаг обрезан.
- `validate(params)` — список понятных ошибок формы (min < max, сумма шансов
  больше нуля, шансы от 0 до 100); пустой список означает «можно запускать».
- `Tally` — счётчик просмотров и действий. `line()` даёт строку журнала:
  «просмотров 14, лайков 3, комментариев 1, подписок 0».

Профили (стартовые, правятся в одном месте):

| | like | comment | favorite | follow | пауза, с |
|---|---|---|---|---|---|
| quiet | 10 | 3 | 5 | 2 | 8–18 |
| normal | 20 | 8 | 10 | 5 | 6–14 |
| active | 30 | 15 | 15 | 10 | 5–10 |

Эти значения консервативнее Laixi (20/20/20/10). Причина: комментарии и подписки
на десятках аккаунтов первыми приводят к блокировке.

## 2. Сюжеты

Файлы лежат в `backend/scenarios/gallery/<ключ>.py`. Формат тот же, что у
остальных сценариев: `NAME`, `DESCRIPTION`, `PARAMS`, `run(ctx)`. Дополнительные
поля для галереи:

```python
GALLERY = {
    "platform": "TikTok",          # подпись и фильтр
    "verified": False,             # «проверено на телефоне»
    "package": "com.zhiliaoapp.musically",
}
```

Общие правила для всех сюжетов:

- `ctx.watch_popups()`, `ctx.humanize()`, `ctx.unlock()` в начале;
- каждое нажатие через `ctx.click_target(...)`: `resourceId`, затем текст, затем
  иконка, координаты только последним запасным вариантом;
- действия, которые меняют аккаунт (лайк, комментарий, избранное, подписка),
  идут через `ctx.budget(...)` с потолком за сутки, по умолчанию включённым;
- `ctx.loop(..., watch=True)` ловит зависание и уход из приложения;
- в конце каждого круга `ctx.log(tally.line())` раз в 5 кругов;
- шаг, не нашедший цель, не роняет сюжет молча: остановка с вопросом идёт
  штатным механизмом фермы.

Сюжеты:

| Ключ | Что делает | Параметры |
|---|---|---|
| `tiktok_feed` | Лента-прогрев: листает, ставит лайк, пишет комментарий из списка, добавляет в избранное, подписывается; меняет слово поиска | профиль, просмотров, слова, фразы, потолки |
| `shorts_autoscroll` | Автолистание любых шортсов (TikTok, YouTube Shorts, Reels): свайп по кривой, пауза, без действий | пакет, просмотров, пауза от и до |
| `spotify_listener` | Ищет слово, запускает трек, слушает целиком или диапазон секунд, ставит лайк | слова, режим прослушивания, диапазон, шанс лайка |
| `vk_feed` | Лента VK: листает, лайкает по шансу | профиль, кругов, потолок лайков |
| `telegram_channels` | Читает каналы: открывает, листает, возвращается; без публикаций | список каналов, кругов, пауза |
| `youtube_shorts` | YouTube Shorts: смотрит, лайкает по шансу | профиль, просмотров, потолок лайков |

Если у телефона нет приложения, `ensure_app` (шаг «Приложение готово») останавливает
сюжет с понятным сообщением, а не вызывает тап вслепую.

## 3. Галерея готовых

**API** (`backend/farm/api/gallery.py`, тонкий слой над `farm/gallery.py`):

- `GET /api/gallery` — список карточек: ключ, название, описание, платформа,
  `verified`, `added` (уже скопирован в «Мои»).
- `POST /api/gallery/{key}/add` — копирует файл в `backend/scenarios/`.
  Имя берётся из тела запроса (необязательно); при совпадении имени
  добавляется суффикс `_2`. Ответ: ключ созданного сценария. Исходник в
  `gallery/` не меняется.

`farm/gallery.py` — читает `backend/scenarios/gallery/`, импортируя только
метаданные (по тому же пути, что `scenarios._load_file`). Файлы из `gallery/` не
попадают в `scenarios.discover()`, поэтому в «Мои» и в запуск не попадают, пока
их не добавили.

**Интерфейс.** В разделе «Сценарии» вкладка «Готовые»: карточка с названием,
платформой, описанием, значком «Не проверено на телефоне» (до тех пор, пока
`verified = False`) и кнопкой «Добавить в мои». После добавления карточка
показывает «Уже в моих» и ссылку на сценарий. Все тексты — в
`frontend/strings/ru.json`. Правила — из `farm-ux`: простой язык, без жаргона,
пустое состояние объясняет, что делать.

## 4. Профили, файлы слов, сводка

- **Профиль:** параметр `profile` (select) в каждом сюжете с действиями. Ручные
  поля (шансы, паузы) переопределяют профиль.
- **Слова и фразы:** параметры типа текст с несколькими строками. Строки
  разбирает `story.parse_lines`, фразы дальше размножает `ctx.phrase`
  (`{привет|здравствуй}`). Загрузка `.txt` — через существующую загрузку файлов
  в форме запуска; если её для параметров нет, в первом шаге остаётся
  многострочное поле.
- **Сводка:** `Tally.line()` в журнале каждые 5 кругов и в конце.

## Ошибки и устойчивость

- Пустой список слов: сюжет листает ленту без поиска, пишет об этом в журнал.
- Пустой список комментариев: комментарии отключены, остальные действия работают.
- Потолок исчерпан (`BudgetReached`): сюжет заканчивается успешно с сообщением,
  как и остальные сценарии с потолком.
- Цель не найдена: штатная остановка и вопрос фермы, не молчаливый пропуск.
- Файл галереи не читается или битый: карточка пропущена, в журнал сервера
  уходит предупреждение; остальные карточки видны.

## Что проверить на живом телефоне (после слияния)

Селекторы приложений записаны по известным `resourceId` и текстам и могут
отличаться в версии на вашем парке. Пока сюжет не прогнали на реальном
телефоне, у него стоит `verified = False`, и галерея это показывает. После
проверки владелец меняет флаг одной строкой.

# Часть 2. Функции из Laixi, которых нет в ферме

Решение владельца 2026-10-25: «сделай все». Девять функций, каждая независима
от остальных и от сюжетов. Не берём: массовые рассылки WhatsApp и RCS, общий
доступ P2P, управление хабом AndroidsBox.

Общие правила. Чистая логика (разбор вывода adb, формирование команд, разбор
файлов) живёт в модулях без adb и диска и покрывается тестами с образцами
вывода. Действия над телефонами идут через таблицу `screen.ACTIONS`, поэтому
сразу доступны из массовых действий (`bulk.ACTIONS` — та же таблица). Тексты
интерфейса — в `frontend/strings/ru.json`, правила — из `farm-ux`.

## F1. Единое разрешение и плотность

- `control/display.py` (чистый): `parse_wm_size(out)`, `parse_density(out)`
  понимают и «Physical size», и «Override size»; `size_command(w, h)`,
  `density_command(dpi)`, `fit_height(w, h, new_w)` — сохранение пропорций.
- Действия `resolution_set` `{width, height, density?}` и `resolution_reset`
  в `screen.ACTIONS`: `wm size WxH`, `wm density N`, `wm size reset`,
  `wm density reset`. Границы: ширина 320–4000, плотность 80–800, иначе 400.
- `GET /api/devices/{serial}/display` — текущие размер, плотность, исходные.
- Интерфейс: массовое действие «Разрешение»: показывает текущее у выбранных
  (если разное — подсказка «у вас N разных»), поля, галка «сохранить
  пропорции», кнопки «Применить» и «Вернуть как было». Сброс кеша размера экрана
  телефона (`adb.screen_size`) после смены.
- Риск: на части прошивок смена размера пересоздаёт активити и обрывает
  трансляцию экрана; интерфейс предупреждает, а «Вернуть» всегда доступна.

## F2. Резервная копия фермы

- `backup.py`: `build(include_adb_key: bool) -> bytes` (zip в памяти),
  `inspect(blob) -> list[str]`, `restore(blob, overwrite) -> report`.
- В архив входят файлы из белого списка `data/` (аккаунты, имена, группы,
  теги, расписание, потолки, настройки, выученные селекторы) и пользовательские
  сценарии из `backend/scenarios/` (кроме `gallery/`). Ключ adb
  (`~/.android/adbkey`, `adbkey.pub`) кладётся **только** при явной галке и с
  предупреждением: это секрет, с ним любой получает доступ ко всем телефонам.
- Восстановление: имена проверяются по белому списку, абсолютные пути и `..`
  отвергаются (zip-slip), общий размер ограничен 64 МБ, файлы пишутся
  атомарно, перед перезаписью текущее сохраняется в `data/.restore-backup/`.
- API: `GET /api/backup?adb_key=0|1` (скачивание), `POST /api/backup/inspect`,
  `POST /api/backup/restore`. Раздел «Настройки», блок «Резервная копия».

## F3. Монитор здоровья

- `health.py` (чистый разбор): `parse_meminfo`, `parse_df`, `parse_cpu_stat`
  (два замера `/proc/stat`), итог `Health {cpu, ram, rom, temp, battery}`.
- `adb.health(serial)` собирает `cat /proc/meminfo`, `df /data`, два замера
  `/proc/stat` через 0.5 с и уже существующий `adb.battery`.
- `GET /api/devices/health` — по всем онлайн-телефонам параллельно, кеш 20 с.
- Пороги в `config.py`: температура ≥ 42 °C, ROM занят ≥ 92%, RAM свободно ≤ 8%.
  Превышение добавляет телефон в «Требуют внимания» с причиной словами
  («греется: 44 °C», «память почти заполнена»).
- Интерфейс: плитка «Здоровье» на ферме — таблица с цветными ячейками,
  сортировка по любому столбцу.

## F4. Пакетный ввод из файла

- Действие `text_lines` `{lines: [...], mode: "order"|"cycle"|"random",
  separator?: str}` в `screen.ACTIONS`: строка N получает N-й выбранный телефон
  (по порядку выбора); `cycle` повторяет строки, если телефонов больше;
  `random` берёт случайную строку; `separator` режет строку, а `{1}`, `{2}`
  в шаблоне подставляют части.
- `lines.py` (чистый): разбор `.txt` и `.csv` (разделитель `;` или `,`,
  кодировка UTF-8 с BOM или без), срезает пустые строки, лимит 5000 строк.
  Excel не читаем (нет зависимости); подсказка «сохраните как CSV».
- Интерфейс: в массовом «Текст» вкладка «Каждому своё» с загрузкой файла и
  предпросмотром «телефон → строка».

## F5. Монитор уведомлений

- `notifications.py` (чистый): `parse(dumpsys_out) -> list[Note]` из
  `dumpsys notification --noredact` (пакет, заголовок, текст, время); терпим к
  разным версиям Android, нераспознанное пропускается.
- `GET /api/devices/notifications?packages=a,b` — по онлайн-телефонам, только
  чтение; список отслеживаемых приложений хранится в `data/notify_watch.json`
  (`GET/PUT /api/notifications/watch`).
- Интерфейс: окно «Уведомления»: сводка «по приложениям — сколько телефонов
  получили», список последних с названием телефона. Видит только шторку
  уведомлений, не содержимое приложений; текст прячется, если приложение в
  списке секретных (банки, коды) — по галке «показывать текст».

## F6. Контакты пакетом

- `contacts.py` (чистый): `generate(prefix, length, count, rng)` (без повторов),
  `parse_file(text)` (строка `+7999...` или `Имя;+7999...`), `insert_cmds(name,
  number)` — команды `content insert` в `raw_contacts` и `data`.
- Действия `contacts_add` `{items: [...]}` и `contacts_clear` в
  `screen.ACTIONS`. Очистка спрашивает подтверждение в интерфейсе.
- Запись через `content provider` работает не на всех прошивках. Если команда
  вернула ошибку разрешений, действие сообщает «этот телефон не даёт писать
  контакты» по каждому телефону, а не падает целиком. Работа на реальном телефоне
  не проверена, это сказано в интерфейсе.

## F7. Публичный API с токеном

- `api/public.py`, префикс `/api/public/v1`, заголовок `X-Farm-Token`, сравнение
  `hmac.compare_digest`. Токен создаёт и перевыпускает владелец в «Настройках»;
  хранится в `data/api_token.json` с правами 0600. Токена нет — публичные
  маршруты отвечают 403.
- Маршруты: `GET /devices`, `GET /devices/{serial}/screenshot`, `POST
  /devices/action` (тот же `ACTIONS`, кроме `shell` — он за отдельной галкой
  «разрешить команды adb» в настройках, по умолчанию выключена), `GET
  /scenarios`, `POST /runs`, `GET /runs/{id}`.
- Документация `docs/public-api.md` с примерами curl и Python.
- Остальной `/api/*` не меняется: ферма слушает только 127.0.0.1.

## F8. Горячие клавиши F1–F9 для фраз

- Только интерфейс: в пульте и в массовом режиме F1–F9 отправляют фразу с тем
  же номером из активной группы быстрых фраз на выбранные телефоны (через
  существующий разворот `{а|б}`). Не срабатывает в поле ввода. Подсказка с
  номерами в списке фраз.

## F9. Помощник-черновик по тексту

- Пользователь описывает задачу словами («открой Telegram, найди канал X,
  пролистай 10 постов»), выбирает один тестовый телефон.
- `vlm/plan.py`: одна просьба к модели (кадр экрана + текст) с требованием
  ответить JSON-списком шагов из разрешённого набора (`launch`, `tap_text`,
  `type`, `swipe`, `wait`, `back`); ответ проходит строгую проверку
  (`parse`), лишнее отбрасывается. Секретные цели отсекает `safety`.
- Результат — **черновик в конструкторе**, который человек читает, правит и
  запускает сам. Автоматического выполнения нет. Работает только при включённом
  помощнике (кадры уходят наружу по явному согласию); считается в общий
  лимит `usage`.
- Если модель вернула невалидный JSON, показывается понятное сообщение, шагов
  нет.

## Порядок и границы

Первая волна: F1, F2, F3, F4, F8. Вторая: F5, F6, F7. Последняя: F9 (зависит от
включённого помощника и самая рискованная). Тесты — для каждой чистой функции,
для таблицы действий (мок `adb.shell`), для API через `TestClient`, JS-тесты
для новых модулей интерфейса по образцу `test_*_js.py`. Проверка на реальных
телефонах не выполнялась, и в интерфейсе функции F1, F5, F6 помечены
«проверьте на одном телефоне».

### Отступления, найденные при реализации

- **F3.** Отдельного эндпоинта нет: таблица «Здоровье» читает данные, которые
  уже приходят с опросом `/api/devices` (RAM/ROM/CPU добавлены в опрос реестра).
- **F7.** Это документация (`docs/public-api.md` и вкладка в «Инструментах»):
  токен `FARM_TOKEN` и 101 маршрут API уже существовали, второго токена нет.
- **F8.** Горячие клавиши F1–F9 работают только в окне массовых действий, не в
  пульте одного телефона.
- **F2.** Экспорт резервной копии идёт методом `POST` (в теле — галка про ключ
  adb), а не `GET`.
- **F9.** Виды шагов черновика другие, чем в спеке: вместо `launch, tap_text,
  type, swipe, wait, back` реализованы `launch_app, open_url, tap(x, y), swipe,
  type, key, sleep`. Нажатия по тексту (`tap_text`) нет: модель задаёт
  координаты по кадру. Черновик не открывается в конструкторе, а сохраняется
  обычным сценарием, его ищут на вкладке «Сценарии».
- **F2.** В копию не входят `vlm.json` (там ключ нейросети — так задумано) и
  сами файлы `data/apks/*.apk`: кладётся только индекс `apks.json`, на новом
  компьютере APK придётся загрузить заново. `vlm_learned.json` и
  `notify_watch.json` в копию входят. Восстановление сценариев (программ,
  которые выполняются на компьютере фермы) включается отдельной галкой; после
  восстановления данных ферму нужно перезапустить (кроме аккаунтов).
- **F1.** `GET /api/devices/{serial}/display` не сделан; размер и плотность
  читает `POST /api/bulk/display`.
- **F4.** `text_lines` — отдельный эндпоинт `/api/bulk/text_lines`, а не
  действие в таблице `screen.ACTIONS`: он недоступен из синхронного режима и
  публичного пути «таблицы действий».
- **F5.** Путь монитора — `/api/notifications`, а не `/api/devices/notifications`;
  в записи уведомления нет времени. Текст скрыт у банков, СМС/мессенджеров и
  всего, что похоже на код.
- **F3.** Таблица «Здоровье» сортируется только по числу проблем, сортировки по
  любому столбцу нет; пороги продублированы в JS (`HEALTH_LIMITS`).
- **Часть 1, §3.** `POST /api/gallery/{key}/add` не принимает своё имя в теле, а
  у карточки «Уже в моих» нет ссылки на сценарий.
