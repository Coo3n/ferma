# Паритет с GeeLark / LaiXi и сверх — дизайн (2026-10-17)

Источник: разбор GeeLark (расписание + шаблоны + прогрев, разброс ±10 %), LaiXi
(скрипт-маркет, задачи по времени), AirDroid (массовые действия, журнал), STF.
Четыре независимых блока, делаются параллельно. Навигация остаётся из четырёх
разделов (правило farm-ux): новое вкладывается внутрь существующих.

## 1. Смены (расписание) — лучше, чем «будильник» у конкурентов

- `farm/schedule.py`, хранение `schedules.json` (gitignored).
- Смена: `{id, name, scenario, params, target:{kind:"all"|"group"|"tag"|"serials", value}, days:[0..6], window:{from:"10:00", to:"14:00"}, runs_per_day:1..10, enabled}`.
- План дня: каждому телефону — свои случайные моменты внутри окна (seed = id+дата+serial, стабилен при перезапуске), не ближе 20 мин друг к другу. Телефоны никогда не стартуют одновременно — это и есть антибан.
- Фоновый поток (старт/стоп в `lifespan` в `farm/server.py`), тик 30 с. Срок наступил → телефон онлайн и свободен → `runner.submit(..., batch="sch-<id>-<дата>")`. Офлайн/занят → повтор каждые 5 мин до конца окна, потом «пропущен».
- API `farm/api/schedule.py`: CRUD `/api/schedules`, `POST /{id}/toggle`, `GET /{id}/plan` (план на сегодня по телефонам со статусами ждёт/запущен/пропущен).
- UI: вкладка «Расписание» в разделе «Запуски» (рядом «Все запуски / Проблемы»), `static/js/schedule.js`, `static/css/schedule.css`. Список смен карточками + «следующий запуск через …», форма в модалке (`openModal`), план дня как полоса-таймлайн 00–24 с точками по телефонам.
- Цель «по тегу» читает `device.tags` (блок 3), если поля нет — `[]`.

## 2. Готовые шаблоны и прогрев

- Новые сценарии в `scenarios/`: `warmup_vk.py`, `warmup_inst.py`, `warmup_tiktok.py`, `warmup_tg.py`, плюс общий модуль `scenarios/_human.py` (человеческое поведение: листание ленты со случайной скоростью/паузами, редкие лайки с вероятностью, случайное время сеанса).
- В каждом: `NAME`, `DESCRIPTION`, `TEMPLATE = True`, `PARAMS` (минуты сеанса, вероятность лайка 0–30 %, «только смотреть»). Никаких логинов/паролей; если приложение не установлено — `ctx.fail` с понятным текстом.
- Загрузчик сценариев отдаёт флаг `template`; в «Сценариях» шаблоны — отдельная группа «Готовые шаблоны» сверху списка, с кнопкой «Запустить…» (только `openRunDialog`) и подсказкой «можно поставить в расписание».

## 3. Теги

- `tags.json` (gitignored) `{serial: [теги]}` в `farm/devices/registry.py`; `Device.tags: list[str]`, в `to_dict`. Группы не трогаем.
- API: `POST /api/devices/{serial}/tags {tags:[...]}`, `POST /api/bulk/tags {serials, add:[...], remove:[...]}`, `GET /api/tags`.
- UI: чипы тегов на плитке (на S скрыты), фильтр по тегу рядом с фильтром группы, массовое «Теги…» для выбранных, в окне запуска цель «по тегу».

## 4. Мелочи из AirDroid / Escrcpy

- Массовый скриншот выбранных → галерея в модалке (картинки по ссылкам на существующий эндпоинт кадра).
- Массовое «Погасить экран» (`input keyevent 223`) — через `ACTIONS` в `farm/api/screen.py`, bulk получает бесплатно.
- «Выгрузить CSV» в «Все запуски»: `GET /api/jobs/export.csv` (время, сценарий, телефон, статус, длительность, ошибка).

## Общие правила

- farm-ux: только токены, русский простой текст, без jargon, `disableWithReason`, `armConfirm` для разрушительного.
- Тесты pytest на серверную логику каждого блока (план смены детерминирован по seed; теги; CSV).
- Общие файлы (`index.html`, `farm/api/__init__.py`, `fleet.js`, `bulk.js`, `.gitignore`) — точечные правки, перечитать при конфликте.
