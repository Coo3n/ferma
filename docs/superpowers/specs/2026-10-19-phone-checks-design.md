# Проверки телефона в сценарии и библиотека APK

Дата: 2026-10-19. Статус: утверждено (дизайн), ждёт плана.

## Зачем

Сценарий сейчас умеет смотреть только на экран («Если на экране»). Системное
состояние телефона он не проверяет: стоит ли приложение, какой версии, хватит
ли заряда, есть ли интернет и место, привязан ли аккаунт. Оператор узнаёт
об этом, когда сценарий падает на середине. Поставить недостающее приложение
из сценария нельзя: APK живут только во временной массовой установке
(`bulk.py:bulk_install` удаляет файл после раздачи).

Выбрано: **A + B**.
- **A** — блок «Если на телефоне» с системными условиями.
- **B** — шаг «Приложение готово»: проверить, при необходимости поставить
  из библиотеки, проверить ещё раз.
- Источник APK — **библиотека на ферме** (один файл на приложение).

Не входит (позже, отдельно): требования сценария в сводке окна запуска
(вариант C); наборы `.apks` / `.xapk`; скачивание APK по ссылке;
автоматическое удаление приложения при несовпадении подписи.

## 1. Что видит человек

### 1.1 Библиотека APK
- Место: раздел **Сценарии → вкладка «Приложения»**. Пятый пункт верхнего
  меню не добавляем.
- Добавление: перетащить `.apk` или кнопка «Добавить APK». Ферма читает
  пакет и версию из файла; название берётся из известных имён (`recApp()`)
  или из имени файла, его можно поправить.
- Строка: «VK · 8.40.1 · 112 МБ · в 3 сценариях», действия «Заменить»,
  «Удалить». Удаление — второй клик (`armConfirm`), текст называет число
  сценариев, которые на него ссылаются.
- APK того же пакета заменяет прежний. Сценарии ссылаются на пакет,
  не на файл, поэтому сразу начинают ставить новую версию.
- Пустое состояние: `emptyBig` — «Приложений пока нет» + одна строка
  + «Добавить APK».

### 1.2 Шаг B «Приложение готово»
- В «Добавить шаг» → группа «Действие».
- Редактор: приложение (выбор по названию, `recApp()` + библиотека),
  «Версия не ниже» (по умолчанию «любая»), галочка «Если нет или старое —
  поставить из библиотеки».
  - Приложения нет в библиотеке → галочка выключена через
    `disableWithReason` («Добавьте APK в Сценарии → Приложения»),
    шаг только проверяет.
- Подпись (`recLabel`): «VK готов (не ниже 8.40), иначе поставить» /
  «VK установлен».
- «Пропустить при неудаче» и «Повторить» работают как у прочих действий.

### 1.3 Блок A «Если на телефоне»
- Группа «Если на экране» в «Добавить шаг» переименовывается в **«Если»**.
  Новые карточки стоят рядом с 👁:

  | Карточка | `check` | Поле |
  |---|---|---|
  | Если приложение есть | `app_installed` | приложение |
  | Если приложения нет | `app_installed`, `negate` | приложение |
  | Если версия ниже… | `app_older` | приложение, версия |
  | Если заряд меньше… | `battery_below` | %, по умолчанию 20 |
  | Если нет интернета | `offline` | — |
  | Если мало места | `space_below` | ГБ, по умолчанию 1 |
  | Если не привязан аккаунт | `no_account` | VK / Instagram / TikTok / Telegram |

- Значок 📱, цвет нейтральный (`--line-hover`), как у `if_seen`.
- «+ иначе» добавляет двойника с обратным `negate`, как у `if_seen`.
- Внутрь кладутся любые шаги (в том числе B и «Закончить сценарий»).
  Вложенность ≤ `BLOCK_DEPTH_MAX`.
- ▶ на заголовке проверяет условие на открытом телефоне и отвечает тостом:
  «VK есть, 8.38.2 — ниже 8.40 → условие выполнено».

## 2. Устройство

### 2.1 Библиотека — `backend/farm/apklib.py`
- Файлы: `DATA_DIR/apks/<package>.apk`. Индекс: `DATA_DIR/apks.json` —
  `{package: {name, version_name, version_code, size, sha256, added}}`.
  Запись индекса атомарная (tmp + rename), как у прочих JSON фермы.
- `add(path, name=None) -> dict`: разбор, проверка, перенос, замена старого.
- `get(package) -> dict | None`, `list() -> list`, `rename`, `remove`.
- `usage() -> {package: n}`: обход сохранённых рецептов, шаги `ensure_app`
  и `if_phone` с этим `package`.
- `install(serial, package, cancel) -> str`: `control.install` под
  семафором **на 4 одновременные установки**; ожидание прерывается
  через `cancel` (`ctx.check_cancel`).

### 2.2 Разбор APK — `backend/farm/apkinfo.py`
- Чистый Python (zipfile + struct): бинарный `AndroidManifest.xml` →
  `package`, `versionCode`, `versionName`, `minSdkVersion`.
- Без новых зависимостей: ферма офлайн, Windows, `aapt` нет.
- Ошибки: не zip, нет манифеста, манифест не читается → `ApkError`
  с причиной словами.

### 2.3 API — `backend/farm/api/apks.py`
- `GET /api/apks` — список + `usage`.
- `POST /api/apks?name=` — загрузка потоком во временный файл, лимит
  1 ГБ, затем `apklib.add`. Отказ: «это не APK», «файл больше 1 ГБ»,
  «наборы .apks/.xapk пока не поддерживаются».
- `PATCH /api/apks/{package}` — название.
- `DELETE /api/apks/{package}`.
- `POST /api/devices/{serial}/phone-check` — `{check, ...}` →
  `{ok: bool, text: "VK есть, 8.38.2"}` для ▶ на блоке A.

### 2.4 Факты о телефоне — `backend/farm/control/facts.py`
- `app_version(serial, package) -> {name, code} | None` —
  `dumpsys package <pkg>` (`versionName=`, `versionCode=`).
- `free_gb(serial) -> float` — `df /data` (учесть форматы toybox и
  busybox, K/M/G).
- `online(serial) -> bool` — из сторожа сети (`devices/network.py`).
- Заряд — существующий `adb.battery`. Аккаунт — `accounts.for_device`.
- `version_lt(a, b)` — сравнение по числовым частям («8.40.1» →
  (8, 40, 1)). Нечитаемо → сравнение `version_code` с кодом из библиотеки;
  нет и его → ошибка «не понять версию VK», а не догадка.

### 2.5 Сценарий — `backend/farm/context.py`
- `ctx.phone_is(check, *, package=None, version=None, percent=None,
  gb=None, platform=None) -> bool` — пишет в журнал словами
  («на телефоне: VK есть, 8.38.2»).
- `ctx.ensure_app(package, min_version=None, install=True) -> None`:
  1. есть и версия ≥ `min_version` → готово;
  2. `install=False` → `StepFailed`;
  3. нет в библиотеке → `StepFailed`;
  4. в библиотеке версия < `min_version` → `StepFailed` до установки;
  5. `apklib.install`, затем снова шаг 1; не вышло → `StepFailed` с причиной.
- Ошибка adb при чтении фактов: один повтор, потом `StepFailed`
  («не удалось узнать заряд»). Ложное «нет» не возвращаем — оно вызвало
  бы лишнюю установку.

### 2.6 Схема шагов — `recorder/steps.py`, `validate.py`, `codegen.py`
- `ARGS["if_phone"] = (("span", "check"), ("negate", "package",
  "version", "percent", "gb", "platform"))`; в `BLOCKS`.
  `validate`: `check` из списка, нужное поле на месте, `percent` 1–99,
  `gb` 0.1–256, `platform` из `accounts.PLATFORMS`.
- `ARGS["ensure_app"] = (("package",), ("min_version", "install"))`;
  в `FLEXIBLE` и `PARAMETRIZABLE`.
- `_LABELS` и `label_of`: «Если на телефоне: VK нет», «VK готов».
- `codegen`: заголовок блока `if [not ]ctx.phone_is(...):`, шаг —
  `ctx.ensure_app(...)`.
- Сохранение: `ensure_app` с пакетом не из библиотеки — предупреждение
  в ответе (не отказ).
- `GET /api/recorder/schema` и `docs/recipe-format.md` дополняются.

### 2.7 Фронт
- `addstep.js`: группа `seen` → «Если» (ключ строки меняется,
  `t('rec.dob_esli')`); карточки `phone_app`, `phone_no_app`, `phone_older`,
  `phone_battery`, `phone_offline`, `phone_space`, `phone_account`;
  `ensure_app` — в «Действие». `addStepPlan` остаётся чистой.
- `blocks.js`: `if_phone` — цвет как у `if_seen`; «+ иначе» — двойник
  с обратным `negate`.
- `recorder.js`: редакторы `if_phone` (поле по `check`) и `ensure_app`;
  `recLabel`; ▶ на `if_phone` → `phone-check`.
- Новый `frontend/js/apklib.js` + `frontend/css/apklib.css` (вкладка
  «Приложения» в разделе сценариев). Загрузка — кнопка блокируется до ответа.
- Все строки — `frontend/strings/ru.json`, в коде только `t()`.
- Видимые слова без жаргона: «приложение», не «пакет»; `package` —
  только в `title` и только после понятного слова.

## 3. Ошибки

| Ситуация | Текст |
|---|---|
| APK нет в библиотеке | «VK нет в библиотеке — добавьте APK в Сценарии → Приложения» |
| В библиотеке версия старее нужной | «в библиотеке VK 8.30, а нужно не ниже 8.40» |
| Нет места | «на телефоне не хватило места» |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | «VK на телефоне подписан иначе — удалите его вручную (данные пропадут)» |
| `INSTALL_FAILED_OLDER_SDK` | «этот VK не ставится на Android N» |
| На телефоне версия новее библиотечной | не ошибка, понижать не пытаемся |
| adb не ответил | один повтор, затем «не удалось узнать …» |
| Отмена в очереди установки | выход из ожидания, обычная отмена запуска |

Причины установки сводятся в существующий `bulk.py:failure` (`bad_apk`,
`no_space`, новые `incompatible`, `older_sdk`), чтобы массовая установка
и шаг говорили одинаково (`BULK_REASONS` на фронте).

## 5. Порядок
1. `apkinfo` + `apklib` + API + вкладка «Приложения».
2. `facts` + `ctx.ensure_app` + шаг B (схема, codegen, редактор).
3. `ctx.phone_is` + блок A (схема, codegen, `addstep`, `blocks`, ▶).
4. Причины установки в `bulk.py`, `recipe-format.md`, скилл `farm-ux`
   (LaiXi-список).

## 6. Отступления при планировании

1. Отдельного `POST /api/devices/{serial}/phone-check` нет: ▶ на блоке идёт обычным `recRunStep`, ответ — строка журнала «на телефоне: …». Тот же путь, что у ▶ на `if_seen`.
2. Группа «Если на экране» не переименовывается: рядом новая группа «Если на телефоне» (ключ `phone`) — семь карточек в одной группе с тремя экранными читались бы стеной.
3. Запасного сравнения по `version_code` нет — нечитаемая версия даёт понятную ошибку.
4. Интернет проверяется `ping` с телефона (8.8.8.8, затем 77.88.8.8); «сторож сети» фермы следит за adb по Wi-Fi, а не за интернетом.
5. Коды причин установки уже есть в `bulk.py` (`signature`, `old_android`, `no_space`, …) — новые не нужны.
6. Шаг «Приложение готово» добавлен как готовое действие (`presets.py`, ключ `ensure_app`) в группе «Действие».
