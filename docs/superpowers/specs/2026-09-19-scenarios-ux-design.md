# Экран сценариев и рекордер: причесать интерфейс

Дата: 19.09.2026. Статус: спек, план ещё не писан.
Продолжает `2026-09-12-branching-scenarios-design.md` — та часть сделала
блоки/отводы/обучение-на-месте/схему рабочими. Эта часть их не трогает,
только переставляет уже существующие экраны так, чтобы ими было понятно
пользоваться.

## Проблема

Функциональность из прошлого спека готова и работает, но два экрана,
которые её показывают, читаются как недоделка:

1. **Список сценариев** (`view-scen`) — заголовок, кнопка записи, голый
   список имён слева, форма параметров справа. Ни структуры сюжета, ни
   состояния здоровья не видно — карточка сценария неотличима от карточки
   пустого файла.
2. **Панель записи** (`pane-rec`) — девять кнопок в один ряд без иерархии:
   Запись, Пауза, Добавить шаг, Якорь, Развилка, Код, Канвас, Схема,
   Сохранить. «Канвас» и «Схема» вдобавок делят одну и ту же иконку
   (`i-layers`), хотя показывают разное. Смысл кнопок объясняют только
   title-подсказки при наведении — на глаз не читается.

Отдельно — то, что казалось «фичи не хватает» (прокликать сюжет мышью,
получить в конце граф, куда стрелками сходятся развилки), на самом деле уже
построено в прошлом спеке: `ctx.run` блоки, отводы через `guard.action.run`,
общий выход, обучение на месте, схема с хребтом и ветками. Не хватает не
функциональности, а того, чтобы её было видно и понятно с первого взгляда.

## Решение

### 1. Список сценариев — карточка показывает структуру и здоровье

Вторая строка карточки вместо пустоты:

```
▸ вход в корзину                          ✎ ✕
  12 шагов · 2 развилки
  ✓ 47/50 · ⚠ 3 преграды
```

- **Структура** (`N шагов · M развилок`) — только у `editable` сценариев,
  считается из recipe (`saver.has_recipe`), для сырых `.py` не показывается:
  там разбирать нечего, а врать числом шагов из логов — хуже, чем молчать.
- **Здоровье** — два числа: доля успешных прогонов за последние
  `MAP_SCAN_JOBS` задач и количество непокрытых преград. Второе — по
  **пакету приложения**, а не по сценарию: `obstacle.uncovered()` в
  `detours.py` уже считает именно так, потому что несколько сценариев могут
  бить в одно приложение. Пакет берём из `PARAMS.package.default`, если он
  задан; если нет — бейдж преград не показываем вовсе, а не гадаем на
  первом попавшемся параметре.

Кнопка запуска остаётся на панели фермы внизу, как сейчас: список сценариев
устройств не выбирает, переносить туда управление запуском — не его работа.

**Бэкенд:** `GET /api/scenarios` начинает отдавать `steps`, `branches`,
`passed`/`failed` за окно и `uncovered` (или `null`, если пакет не задан).
Считается тем же способом, что и текущая карта отводов — переиспользуем
`obstacle.uncovered()` и сканирование последних задач, не новую подсистему.

### 2. Экран записи — устройство и схема рядом

Компоновка меняется с «устройство + список шагов» на «устройство + схема»:
левая колонка — экран телефона, как сейчас; правая, где раньше рос список
шагов, — сама схема (бывшие «Канвас» и «Схема» в одном месте, визуальный
язык не меняется: хребет из прошлого спека, стрелки вниз — шаги, `◇` вбок —
развилка, `✕` — непокрытая преграда из журнала с кнопкой «Показать выход»).
Схема растёт по мере кликов по экрану устройства — это и есть «прокликал
сюжет — сбоку сложилась карта».

«Список шагов» и «Код» никуда не делись, но превращаются в переключатель
вида над схемой (`Схема / Список / Код`), а не в кнопку одного веса с
«Записью». На узких окнах переключатель ведёт себя как вкладка: схема или
устройство видны по очереди, не сжимаются вдвое.

### 3. Панель инструментов — группы вместо ряда

Было: `Запись · Пауза · Добавить шаг · Якорь · Развилка · Код · Канвас ·
Схема · Сохранить` — девять кнопок, один уровень.

Стало — три подписанные группы:

```
ЗАПИСЬ        Запись   Пауза
ДОБАВИТЬ      Шаг   Якорь экрана   Развилка
ВИД           ◉ Схема   ○ Список   ○ Код          [Сохранить сценарий]
```

«Развилка» и «Якорь экрана» остаются теми же словами (это не жаргон, это
предметные термины сценария — переименование не решает путаницу, решает
контекст группы «Добавить»). Пропадают только «Канвас» и «Схема» как два
равных пункта с одинаковой иконкой — вместо них один переключатель вида.
«Сохранить сценарий» — единственная primary-кнопка экрана, всё остальное
визуально вторично.

## Данные и бэкенд

Единственная новая работа на бэкенде — пункт 1: посчитать `steps`,
`branches`, `passed/failed`, `uncovered` и отдать их в `GET /api/scenarios`.
Всё остальное — фронтенд поверх уже существующих `/api/recorder/*`,
`/api/detours`, `/api/jobs` и схемы из прошлого спека.

## Не-цели

- Свободный холст со стрелками произвольной формы — решение из прошлого
  спека не пересматривается: `run(ctx)` линейна, схема не может обещать
  больше этого.
- Перенос кнопки «Запустить» на экран сценариев.
- Новая цветовая палитра или типографика — только токены `base.css`.
- Переименование «Развилка»/«Якорь экрана» — путаницу решает группировка,
  не смена слов.

## Этапы

1. Бэкенд: посчитать структуру и здоровье в `GET /api/scenarios`.
2. Список сценариев: вторая строка карточки.
3. Слияние «Канвас»+«Схема» в один правый блок экрана записи.
4. Перегруппировка панели инструментов на три ряда с подписями.

Каждый этап самостоятельно полезен и не ломает предыдущие; можно
останавливаться после любого.
