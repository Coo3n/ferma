# Шаги сюжетов, группы фраз и ИИ-агент

Дата: 2026-10-26. Продолжает `2026-10-25-ready-stories-design.md`.
Решения владельца: (1) сюжеты, которые укладываются в шаги конструктора,
становятся рецептами и правятся в конструкторе, остальные остаются кодом с
читаемым списком шагов; (2) агент идёт пошагово с «ок» на одном телефоне,
режим «сам» ограничен числом шагов; (3) интерфейс должен быть заметно лучше
обычного: быстрый, понятный, без жаргона.

## Общие правила интерфейса

- Дизайн-система «графитовая консоль» (`frontend/design/tokens.css`): только
  токены (`--fs-1..5`, `--r1..3`, `--accent`, `--bad`, `--warn`, `--busy`,
  `--panel…`), шрифт Golos Text, никаких hex, rgba и кеглей в px.
- Один основной (зелёный) ярлык на панель. Тихие кнопки без рамок. Разрушающее
  действие — второй клик (`armConfirm`), без `confirm()`.
- Слова: «телефон», «запуск»; без `adb`, `shell`, «пакет», «селектор».
- **Новые строки интерфейса — в `frontend/strings/ru.json`** (`data-t` и `t()`),
  не литералами в коде.
- Пустые состояния: заголовок + одна строка + кнопка (`emptyBig`).
- Клавиатура: у каждого нового экрана видна подсказка клавиш, фокус видим,
  Esc закрывает только своё окно.
- Проверка ширин 1280 и 1728: без переносов и горизонтальной прокрутки.
- Состояния всегда явные: загрузка (скелетон или «Думаю…» с движением),
  ошибка словами с кнопкой «Повторить», пусто, успех. Обновления без
  «прыжков» вёрстки.

## Часть A. Шаги добавленного сюжета видны и правятся

### A1. Источники сюжетов в галерее
Галерея читает два вида файлов в `backend/scenarios/gallery/`:
- `<ключ>.recipe.json` — рецепт конструктора: `{"gallery": {"platform",
  "verified", "package"}, "key", "meta", "params", "steps"}`. «Добавить в мои»
  сохраняет его как обычный записанный сценарий (`recorder.save`), поэтому он
  открывается в конструкторе. Ключ копии уникален (`_2`, `_3`).
- `<ключ>.py` — код, как раньше; в нём необязательный список
  `STEPS = ["Открывает TikTok", …]` — читаемое описание для показа.
Карточка получает поля `editable` (рецепт — `true`), `steps_text` (список
строк), `kind` (`recipe` | `code`).

### A2. Описание шагов словами
Чистый модуль `farm/steps_text.py`: `describe(steps) -> list[{"text",
"depth"}]` по рецепту (вложенность блоков = `depth`). Фразы человеческие:
«Открыть приложение», «Повторять 30 раз», «С шансом 20%: нажать «Нравится»»,
«Пауза 6–14 с», «Потолок за сутки: лайки — 200», «Провести вверх». Без
классов, id и координат. Неизвестный вид шага — «Шаг: <вид>», не падение.

### A3. Какие сюжеты рецепты
- Рецептами: автолистание шортсов, лента VK, YouTube Shorts, Spotify (одно
  слово за запуск, диапазон секунд задан паузой), Telegram (один канал за
  запуск). Повторы по списку — числом запусков. Код-версии автолистания, VK и
  YouTube Shorts удаляются (рецепт их заменяет без потери); Spotify и Telegram
  «по списку» остаются кодом под названиями «… (по списку)».
- Кодом остаётся TikTok (структурный поиск, бюджет времени на видео) с `STEPS`.
- Все новые рецепты проходят тест: принимаются `schema.normalize_steps`,
  собираются `codegen.render`, проходят `recorder.validate`.

### A4. «Сценарии»: читаемые шаги у кодовых сценариев
`Scenario.steps_text` берётся из `STEPS` модуля. В панели выбранного сценария
(там, где рецепту показывают число шагов) кодовый сценарий со `STEPS` получает
сворачиваемый блок «Что делает» с этим списком и подписью «Правится только
через параметры формы». У рецептов блок тоже есть (из `describe`) рядом с
кнопкой «Открыть в конструкторе».

### A5. Интерфейс галереи (крутой)
- Шапка вкладки: поиск, фильтр по платформе (чипы: Все · TikTok · VK · YouTube ·
  Telegram · Spotify), счётчики.
- Карточка: плитка платформы с цветом и буквенной меткой, название, одна строка
  описания, **бейджи** «Правится в конструкторе» (зелёный) / «Только параметры»
  (серый), «Не проверено на телефоне» (янтарный) с подсказкой.
- «Что делает»: сворачиваемый список шагов с отступами по вложенности и
  номерами; раскрывается по клику на заголовок и по `Enter`/`Space`.
- Действия карточки: основной ярлык «Добавить в мои». После добавления тост
  «Добавлено» с кнопкой «Открыть» (рецепт — в конструктор, код — в сценарий);
  карточка показывает «Уже в моих» и ссылку «Открыть».
- Предпросмотр без добавления: клик по карточке раскрывает полный список шагов
  и параметры (метки полей) — человек видит, что получит.
- Пустое состояние и состояние ошибки по общим правилам. Работает с клавиатуры
  (стрелки между карточками, `Enter` — раскрыть, `A` — добавить).

## Часть B. Группы фраз

### B1. Хранение и API
Файл `data/phrases.json`: `{"groups": [{"id","name","items":[строки]}],
"active": "<id>"}`. Не больше 30 групп, 100 фраз в группе, фраза до 500
символов. API: `GET /api/phrases`, `PUT /api/phrases` (вся структура, валидация
и очистка на сервере), `POST /api/phrases/import` (текст `.txt`/`.csv`, по
строке на фразу, `{"group": id|null, "text": …}`), `GET /api/phrases/export?group=id`
(UTF-8 с BOM, `.csv`). Файл входит в резервную копию (`backup.py` EXTRA_DATA).
Чистый модуль `farm/phrase_store.py` (разбор, очистка, лимиты, миграция).

### B2. Переезд из браузера
При первом открытии панели «Ввести текст», если на сервере групп нет, а в
`localStorage` (`farm.phrases`) есть список, он один раз уходит в группу
«Общие»; ключ в браузере после успешного ответа очищается по точному имени.

### B3. Интерфейс
В панели «Ввести текст» вместо плоского списка:
- Вкладки групп с «+», двойной клик или `F2` — переименовать, у активной «⋯» с
  «Удалить группу» (двойное подтверждение). Активная группа запоминается на
  сервере.
- Фразы — аккуратные плашки с номером клавиши **F1–F9** (первые девять),
  остальные без клавиши; клик вводит фразу на выбранных телефонах, «×» —
  удалить; перетаскивание для порядка не нужно (YAGNI).
- Быстрый ввод новой фразы прямо в строке «Добавить фразу» (`Enter` —
  сохранить), счётчик вариантов `{а|б}` («вариантов: 6») подсказкой.
- Импорт/экспорт: «Загрузить файл» и «Скачать группу».
- F1–F9 работают по активной группе (переключение вкладки меняет клавиши;
  подсказка «F1–F9 — фразы группы «…»» видна в панели).

## Часть C. Текстовый ИИ-агент

### C1. Поведение
Окно «Инструменты → ИИ-агент» (заменяет плитку «Черновик по описанию»; режим
«только составить список» остаётся кнопкой «Составить сразу, без выполнения»).
1. Выбор одного телефона, поле «Что сделать?», примеры-подсказки.
2. Нажали «Начать»: агент смотрит на кадр и предлагает **одно** действие.
3. Режим по умолчанию — «Спрашивать каждый шаг»: кнопки «Выполнить» (`Enter`),
   «Пропустить» (`S`), «Остановить» (`Esc`). Режим «Выполнять сам, не больше N
   шагов» (по умолчанию 15, максимум 30) включается переключателем с
   подтверждением; кнопка «Стоп» всегда видна.
4. Агент заканчивает ответом «готово» или «нужен человек» с причиной.
5. После завершения — «Сохранить как сценарий» (рецепт из выполненных шагов,
   имя «Агент: <задача>»), его потом править в конструкторе и запускать на всём
   парке без нейросети.

### C2. Безопасность
- Разрешённые действия: нажать (x, y), провести, ввести текст, клавиша, открыть
  приложение, открыть ссылку, подождать. **Нет** shell и любых команд системы.
- Отказ и остановка: нейросеть выключена в настройках; задача или вводимый текст
  похожи на секрет (`safety.secret_goal`); экран с полем пароля/кода
  (`safety.secret_screen`) или защищённый экран; исчерпан лимит шагов агента или
  дневной лимит нейросети; два одинаковых действия подряд без изменения экрана
  (зацикливание); любая ошибка телефона.
- Каждый шаг пишется в журнал агента (в окне): время, действие, «почему»,
  результат. Лимиты — общие с остальной нейросетью (`vlm.usage`), плюс
  отдельный потолок шагов одного сеанса (`config.AGENT_MAX_STEPS`, по умолчанию
  30).
- Исполняет действие **сервер**, после проверки вида и аргументов; браузер не
  может прислать произвольное действие через агента.

### C3. API
- `POST /api/vlm/agent/step` `{serial, task, history}` → `{action | done | ask,
  why, step_no, left}`; не меняет телефон.
- `POST /api/vlm/agent/do` `{serial, action}` → выполняет проверенное действие,
  возвращает `{ok, changed}`.
- `POST /api/vlm/agent/recipe` `{task, history}` → рецепт для
  `POST /api/recorder/save`.
Чистый модуль `farm/vlm/agent.py` (разбор ответа, проверка действия, детектор
зацикливания, сборка рецепта).

### C4. Интерфейс (крутой)
- Раскладка во всё окно (`modalSheet('wide')` или крупнее): слева кадр телефона
  (живой, обновляется после каждого шага), справа **лента шагов** как диалог:
  карточки «Агент предлагает» → «Выполнено» / «Пропущено» / «Остановлено».
- Предложенное действие показывается **на кадре**: метка-прицел в точке нажатия
  с мягким пульсом, стрелка для свайпа, плашка с текстом для ввода.
- Под лентой — панель управления: «Выполнить», «Пропустить», «Стоп», переключатель
  «Выполнять сам» с полем «шагов», индикатор «шаг 4 из 15» и расход лимита.
- Состояния: «Смотрю на экран…» (анимированные точки), «Жду вашего ответа»
  (подсветка кнопки «Выполнить»), «Выполняю…», «Готово» (зелёная галочка),
  «Нужен человек» (янтарная плашка с причиной словами), «Остановлено».
- Ошибки словами с кнопкой «Повторить шаг». Все тексты — в `ru.json`.
- Уважает `prefers-reduced-motion`.

## Порядок и границы
A → B → C. Вне объёма: управление многими телефонами агентом, голосовой ввод,
синхронизация фраз между компьютерами, перетаскивание порядка фраз.
Проверка на живых телефонах не проводилась; рецепты и агент помечены «проверьте
на одном телефоне».
