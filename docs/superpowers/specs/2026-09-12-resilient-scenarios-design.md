# Устойчивые сценарии: стабильность, стражи, резолвер, якоря

Дата: 12.09.2026. Статус: одобрен, ждёт план имплементации.

## Проблема

Один и тот же сценарий должен доходить до цели на каждом устройстве фермы.
Сейчас прогоны ломают четыре вещи:

1. **Неожиданные экраны** — попапы, онбординги, A/B-варианты: путь к цели
   на разных устройствах разный.
2. **Селекторы не находятся** — Compose без `resourceId`, WebView без узлов:
   элемент виден глазами, но не через accessibility-дерево.
3. **Разные прошивки и локали** — «Разрешить» на MIUI, «Allow» на Samsung:
   текстовые селекторы разъезжаются.
4. **Флакинесс таймингов** — медленный девайс не дорисовал экран, клик ушёл
   в пустоту.

Сценарии пишутся рекордером и правятся руками, поэтому устойчивость обязана
попадать в сгенерированный код автоматически, а не требовать ручной обвязки.

## Цели

- Сценарий остаётся линейным читаемым `.py`; вся устойчивость — под капотом
  `ctx` и в сгенерированном коде рекордера.
- Каждый слой устойчивости работает и приносит пользу независимо от остальных.
- Ферма без vision-зависимостей работает ровно как сейчас.
- Старые записанные сценарии остаются валидными без изменений.

## Не-цели

- Полноценный state machine (граф экранов с переходами) — сознательно нет:
  якоря дают 80% пользы без переписывания рекордера и потери читаемости.
- Поддержка игр/SurfaceView как основного кейса — template matching появится,
  но цели фермы — нативные приложения и Compose/WebView-гибриды.
- UI-редактор стражей — в этой итерации стражи задаются файлами.

## Архитектура: четыре слоя

```
шаг сценария
  └─ ctx._settle()          слой 1: дождаться стабильности экрана
  └─ resolve(target)        слой 3: селекторы → текст → OCR → шаблон → координаты
  └─ действие (тап/ввод)
  └─ при падении шага:      слой 2: стражи → один повтор → fail с артефактами
ctx.expect_screen(...)      слой 4: якорь — «я на том экране?» до первого клика
  └─ при несовпадении:      слой 2: стражи → пересверка → fail
```

Порядок внедрения = порядок нумерации: (1+2) → 3 → 4, каждый этап шипится
отдельно.

## Слой 1. Стабильность экрана — `farm/control/stability.py`

`wait_stable(serial, timeout=3.0, quiet=0.4) -> bool`

- Раз в `quiet` секунд снимает дамп иерархии, сравнивает хэш с предыдущим.
  Два одинаковых подряд → экран дорисован, возврат `True`.
- Таймаут (вечный спиннер, анимированный баннер) → возврат `False`,
  шаг **идёт дальше** — стабильность best-effort, не гейт.
- Интеграция: приватный `ctx._settle()` перед `click`, `click_any`,
  `click_target`, `type`, `set_text`. Выключение: `ctx.settle = False`
  на весь сценарий или env `FARM_SETTLE=0` на всю ферму.
- Цена: ~0.5–1 с на шаг (два дампа). Приемлемо: лечит самый частый флак.

## Слой 2. Стражи — `farm/guards.py` + папка `guards/`

Декларативный реестр известных перехватчиков: «если на экране X — сделай Y
и продолжи сценарий».

### Формат

JSON (консистентно с `devices.json`/`network.json`), горячая перезагрузка
как у сценариев. `guards/global.json` — всегда активны;
`guards/<package>.json` — активны, когда `ctx.current_app()` совпадает.

```json
[
  {
    "name": "permission-allow-ru",
    "when": {"any": [{"text": "Разрешить"}, {"resourceId": "com.android.permissioncontroller:id/permission_allow_button"}]},
    "action": {"click": {"text": "Разрешить"}},
    "max_fires": 3
  },
  {
    "name": "rate-us-dismiss",
    "when": {"any": [{"textContains": "Оцените приложение"}]},
    "action": {"key": "back"},
    "max_fires": 2
  }
]
```

- `when.any` — список u2-селекторов, страж срабатывает, если найден хоть один.
- `action` — ровно одно из: `click` (u2-селектор) или `key` (имя клавиши).
- `max_fires` — потолок срабатываний за один прогон задачи (по умолчанию 3):
  защита от зацикливания «страж жмёт — попап возвращается».
- Каждое срабатывание пишется в журнал задачи: имя стража, что нажал.

### Точки вызова

1. **Падение шага**: `click`/`click_any`/`click_target`/`expect_screen`
   не нашли цель → `guards.try_all(ctx)` → сработал хоть один →
   **один** повтор шага → снова мимо → обычный fail с артефактами.
2. **Несовпадение якоря** (слой 4) — та же схема.

`ctx.watch_popups()` (u2-watchers) остаётся как быстрый фоновый слой;
стражи — медленный, но сильный: произвольные селекторы, произвольные действия,
журналирование, лимиты.

### Комплект по умолчанию

`guards/global.json` из коробки: permission-диалоги ru/en (сток,
MIUI/HyperOS, One UI), «приложение не отвечает» → «Подождать»,
Google Play «продолжить без аккаунта»-класс диалогов.

## Слой 3. Многослойный резолвер — `farm/resolve.py` + `farm/vision/`

Цель шага — пакет слоёв, а не один селектор.

### Цель (target)

```python
ctx.click_target(
    sel=[dict(resourceId="com.app:id/login"), dict(description="Войти")],
    text=["Войти", "Log in"],
    img="07_login.png",          # кроп из scenarios/<имя>_assets/
    at=(0.52, 0.81),             # нормализованные координаты
)
```

Все поля опциональны, хотя бы одно обязано быть. `ctx.click(**sel)` и
`ctx.click_any(...)` не меняются и работают как раньше (внутри `click_any`
переезжает на резолвер).

### Порядок разрешения

| # | Слой | Механизм | Условие пропуска |
|---|------|----------|------------------|
| 1 | Селекторы | цепочка u2, быстрые круги как в `click_any` | `sel` пуст |
| 2 | Текст по дампу | точное → contains → casefold → fuzzy (difflib ratio ≥ 0.85) + словарь синонимов ru/en | `text` пуст |
| 3 | OCR | скриншот → боксы текста → то же сопоставление → тап в центр бокса | `text` пуст или OCR-бэкенд недоступен |
| 4 | Шаблон | OpenCV `matchTemplate`, multiscale 0.7–1.3, порог 0.85, тап в центр совпадения | `img` пуст или OpenCV недоступен |
| 5 | Координаты | тап в нормализованную точку | `at` пуст |

Результат — `Hit(x, y, layer, detail)`. Слой ≠ 1 логируется в журнал задачи:
«цель найдена OCR („Войти“), селекторы не совпали» — сигнал починить сценарий.

### Словарь синонимов

`farm/vision/synonyms.py`: пары ru/en для типовых кнопок
(Разрешить/Allow, Далее/Next, Пропустить/Skip, Принять/Accept, ОК/OK, …).
Применяется в слоях 2 и 3: искомый текст расширяется синонимами.

### OCR-бэкенды — `farm/vision/ocr.py`

Подключаемые, автовыбор при старте:

- **`vision`** (macOS): Apple Vision через пакет `ocrmac`. Быстрый, отличный
  ru/en, зависимостей минимум. Дефолт на darwin.
- **`tesseract`**: `pytesseract` + системный tesseract. Fallback для Linux.
- Ни одного → слой 3 выключен, один лог «OCR недоступен» на прогон.

Интерфейс: `ocr(image_bytes) -> list[Box(text, x1, y1, x2, y2, conf)]`.

### Шаблоны

- Рекордер в момент записи клика вырезает кроп цели по bounds найденного
  элемента (bounds уже есть — рамка на миниатюре рисуется по ним).
- Кроп кладётся в `scenarios/<имя>_assets/NN_<метка>.png` при сохранении
  сценария; в коде — относительное имя файла.
- Multiscale обязателен: устройства с разным разрешением. Базовый масштаб —
  отношение ширины экрана прогона к ширине экрана записи; перебор — базовый
  ×0.85, ×1.0, ×1.15, обрезанный диапазоном 0.7–1.3.
- Удаление записанного сценария удаляет и его `_assets`.

## Слой 4. Якоря экранов — рекордер + `ctx.expect_screen`

```python
ctx.expect_screen("login", any=[dict(resourceId="com.app:id/title"),
                                dict(text="Вход")], timeout=10)
```

### Поведение в ранере

1. Ждать до `timeout`, пока найдётся хоть один признак из `any`.
2. Не нашлось → `guards.try_all(ctx)` → сработали → пересверка.
3. Снова нет → `StepFailed`: «ожидал экран «login», вижу
   `<текущая activity>`: [верхние тексты экрана]» + в артефакты пара
   `expected_login.png` (миниатюра записи из `_assets`) и `actual.png`.

Чужой экран ловится до клика, а не через три шага кликов в пустоту.

### Поведение в рекордере

- Рекордер следит за сменой экрана: сменилась activity или изменилась
  большая часть узлов дампа (стартовый порог — 40%, уточняется на живых
  записях) → новый экран.
- На первом действии на новом экране — вставить шаг `expect` с 1–3
  стабильными признаками (лучшие кандидаты по той же логике, что у
  инспектора: resourceId → description → text) и миниатюрой экрана.
- Шаг `expect` в конструкторе виден, редактируем и удаляем как обычный шаг.

## Изменения данных и кодегена

`farm/recorder/steps.py`:

- `click` получает опциональные поля `texts: list[str]`, `crop: str`,
  `point: (x, y)` — валидируются в `normalize_step`.
- Новый kind `expect`: обязательный `name`, обязательный непустой список
  селекторов `any`, опциональный `thumb`.

`farm/recorder/codegen.py`:

- `click` с любым из новых полей → рендер `ctx.click_target(...)`;
  без них — как сейчас (`ctx.click` / `ctx.click_any`).
- `expect` → рендер `ctx.expect_screen(...)`.

`farm/recorder/save.py`: сохранение кропов и миниатюр в
`scenarios/<имя>_assets/`, удаление вместе со сценарием.

Обратная совместимость: старые `.py` не трогаются; старые записи
конструктора без новых полей проходят `normalize_step` как раньше.

## Телеметрия

В журнал задачи, по каждому шагу: слой разрешения, время `_settle`,
срабатывания стражей. В конце прогона — сводка:
«3 шага спасены запасными слоями (2 OCR, 1 шаблон), 2 стража сработали —
обнови селекторы в шагах 4, 7, 12». Сводка попадает в артефакты задачи.

## Зависимости

`requirements-vision.txt` (опционально): `opencv-python-headless`, `numpy`,
`ocrmac; sys_platform == "darwin"`, `pytesseract; sys_platform != "darwin"`.
Основной `requirements.txt` не меняется. Импорты vision — ленивые, внутри
`farm/vision/`; их отсутствие выключает слои OCR и шаблонов в резолвере,
остальное работает как сейчас.

## Тестирование (всё без устройства, в стиле существующих тестов)

- `test_stability.py` — фейковая последовательность дампов: стабилизация,
  таймаут на вечной анимации.
- `test_guards.py` — фейковый ctx: срабатывание, `max_fires`, пер-приложение,
  битый JSON стража не роняет остальных.
- `test_resolver.py` — фейковые дампы: порядок слоёв, fuzzy-сопоставление,
  синонимы, «хотя бы одно поле».
- `test_vision.py` — golden-фикстуры: OCR находит текст на эталонном
  скриншоте, matchTemplate находит кроп при 0.7×/1.3×; `pytest.skip`,
  если vision-зависимости не установлены.
- Расширение `test_recorder_steps.py` / `test_recorder_codegen.py` —
  новые поля и kind `expect`.

## Этапы внедрения

1. **Стабильность + стражи** — лечит попапы и тайминги. Виден эффект сразу
   на существующих сценариях без перезаписи.
2. **Резолвер + кропы в рекордере** — лечит Compose/WebView и локали.
   Новые записи получают слои автоматически.
3. **Якоря** — лечит A/B-развилки и даёт внятные падения
   «ожидал X, вижу Y».

## Решённые вопросы

- OCR-дефолт — Apple Vision (`ocrmac`): ферма живёт на macOS.
- Формат стражей — JSON, не YAML: без новой зависимости, консистентно
  с остальными конфигами фермы.
- Имя API — `ctx.click_target`; `ctx.click`/`ctx.click_any` не трогаем.
- State machine целиком — отклонён в пользу якорей (см. «Не-цели»).
