# Конструктор сценариев (Record & Play)

Дата: 2026-07-26

## Задача

Сценарии пишутся руками в `scenarios/*.py`. Это требует знания API `ctx` и
поиска селекторов через инспектор с копированием строк в редактор. Нужен режим,
в котором сценарий собирается кликами по живому экрану: каждое действие
превращается в шаг, шаги ревьюются и сохраняются готовым `.py`-файлом.

## Что уже есть и переиспользуется

- `GET /api/devices/{serial}/inspect` отдаёт `{screenshot, nodes[]}`, где у
  каждого узла есть `bounds`, `target` (clickable-предок) и `selectors[]` —
  готовые строки вида `ctx.click(resourceId="…")` с полем `matches`.
- `farm/ui/selectors.py` уже реализует приоритет `resourceId → description →
  text → связка с className → instance → координаты` и считает однозначность.
- `static/js/screen.js` уже шлёт тапы, свайпы, долгие нажатия, текст и клавиши
  через единственную функцию `act(payload)`.
- `static/js/inspector.js` уже содержит hit-test по наименьшей площади
  (`inspHit`) и отрисовку рамок.
- `farm/scenarios.py` перечитывает папку по mtime — сохранённый файл появляется
  в списке без перезапуска сервера.

Рекордер это потребляет и ничего из перечисленного не переизобретает.

## Решения

| Развилка | Выбор |
|---|---|
| Как узнаётся элемент под кликом | Дамп кэшируется вперёд: читается при старте записи и заново после каждого действия. Клик делает hit-test по кэшу мгновенно, тап летит на устройство без задержки |
| Набор действий v1 | Жесты (тап, долгий тап, свайп), ввод текста, клавиши, `unlock`, плюс `launch_app` / `open_url` / `stop_app` со вкладки «Устройство». Ручные шаги: `sleep`, `screenshot` |
| Где живёт сессия | Шаги в памяти вкладки, автосохранение черновика в `localStorage`. Генерация кода и запись файла — на сервере, Python |
| Параметризация | Ручное вынесение значения шага в `PARAMS` кнопкой `{}` |
| Обратное открытие `.py` в конструкторе | Нет. Генерация одноразовая, дальше файл правится как обычный код |
| Место в интерфейсе | Внутри вкладки «Сценарии», вторым режимом. Отдельной вкладки нет |

## Архитектура

### Новые юниты

| Юнит | Ответственность | Зависимости |
|---|---|---|
| `farm/recorder/steps.py` | схема всего, что приходит из браузера: шаги, `params`, `meta`. Нормализация и валидация | нет |
| `farm/recorder/codegen.py` | `{meta, params, steps}` → текст `.py`. Чистая функция | `steps` |
| `farm/recorder/save.py` | запись в `scenarios/<key>.py`, валидация ключа, защита от выхода за папку | `config`, `codegen` |
| `farm/api/recorder.py` | `POST /api/recorder/preview`, `POST /api/recorder/save` | всё выше |
| `static/js/recorder.js` | состояние `REC`, перехват действий, список шагов, правка, оверлей рамок | `core.js` |
| `static/css/recorder.css` | стили панели конструктора и оверлея | — |
| `tests/test_recorder.py` | тесты кодгена, валидации шагов и сохранения | pytest |

`codegen.py` не знает про `adb` и FastAPI — то же правило тестируемости, что
уже зафиксировано в `docs/GOTCHAS.md` для `farm/ui/tree.py`.

### Правки существующего

- `static/js/screen.js` — в `act(payload)` одна строка:
  `if (window.REC?.on) recNote(payload)`. Точка перехвата ровно одна: через
  `act()` идут не только жесты, текст и клавиши, но и `launchPkg` / `stopPkg` /
  `openUrl` со вкладки «Устройство» — у них типы `launch`, `stop`, `url` того же
  эндпоинта `/api/devices/{serial}/action`. `device-tools.js` не меняется.
- `static/js/scenarios.js` — кнопка «✎ Создать сценарий», переключение режимов
  панели, значок `✒` и удаление для записанных сценариев.
- `static/index.html` — разметка режима «конструктор» внутри `#pane-scen`,
  подключение `recorder.js` и `recorder.css`.
- `farm/scenarios.py` — поле `recorded: bool` в `Scenario`, читается из атрибута
  модуля `RECORDED`, отдаётся в `to_dict()`.
- `farm/api/scenarios.py` — `DELETE /api/scenarios/{key}`.
- `farm/api/__init__.py` — `include_router(recorder.router)`.
- `README.md`, `docs/GOTCHAS.md` — новые разделы.

## Интерфейс

Вкладка «Сценарии» получает два режима внутри `#pane-scen`.

**Режим «список»** (по умолчанию) — текущий вид: список сценариев, форма
параметров, «▶ Запустить на выбранных». Добавляются:
- кнопка «✎ Создать сценарий» в шапке — переключает панель в конструктор;
- значок `✒` у сценариев с `RECORDED = True`;
- кнопка удаления у них же, с подтверждением.

**Режим «конструктор»** — шапка `← назад`, кнопки `● Запись` / `⏸ пауза` /
`■ стоп`, список шагов, кнопки `+ пауза` и `+ скриншот`, `⟨⟩ код`,
`💾 Сохранить`.

Центральная колонка остаётся общим живым экраном. Устройство берётся то,
которое открыто (`S.active`), отдельного выбора в конструкторе нет.

### Клик в режиме записи

Делает три вещи разом:

1. летит на устройство обычным тапом — иначе флоу не продвинуть;
2. подсвечивается рамкой найденного узла, как в инспекторе;
3. падает в список шагов с готовой строкой кода и меткой однозначности
   (`✓` при `matches == 1`, иначе `⚠3`).

Визуально это инспектор, но кадр не заморожен и клик проходит насквозь. Оверлей
рамок рисуется по кэшированному дампу со стилем `pointer-events: none`, hit-test
использует ту же логику наименьшей площади, что `inspHit()`.

После каждого действия дамп перечитывается (0.3–1.5 с). На это время рамки
скрываются и в панели горит «обновляю…». Тап при этом уже произошёл — отстаёт
только подсветка.

### Инспектор и запись взаимоисключающие

Инспектор замораживает кадр и поглощает клики, запись требует живого экрана и
проходящих тапов. Включение записи вызывает `inspectorOff()`, включение
инспектора останавливает запись.

### Ревью шагов

Строка шага показывает номер, иконку, человекочитаемую метку («Кнопка «Войти»»,
«Ввод: qwerty123»), сгенерированную строку кода и метку однозначности.

Действия по строке:
- `⌫` — удалить шаг;
- `✎` — править: изменить текст или число секунд, **либо выбрать другой
  селектор** из тех же альтернатив, что показывает инспектор;
- `⇅` — переставить шаг;
- клик по строке разворачивает миниатюру момента с рамкой цели — скриншот
  приходит в ответе `/inspect`, отдельного запроса не нужно;
- `{}` — вынести значение в `PARAMS`.

`⏸ пауза` оставляет экран живым и кликабельным, но шаги не пишутся: состояние
поправить руками, не засоряя запись. `■ стоп` закрывает запись, шаги остаются.

## Модель шага

В браузере:

```js
{
  id: 12,
  kind: 'click',
  args: {},
  selector: {call: 'click', args: 'resourceId="…"', matches: 1, fragile: false},
  alts: [/* остальные selectors[] узла */],
  label: 'Кнопка «Войти»',
  warn: '',
  param: null,
  shot: 'data:image/jpeg;base64,…',
  bounds: [0.1, 0.4, 0.9, 0.47]
}
```

`shot`, `alts`, `bounds` нужны только интерфейсу ревью. На сервер уезжает
`{kind, args, selector, param, note}`, где `note` — та же метка, что показана в
списке: генератор кладёт её комментарием в конец строки.

Автосохранение черновика в `localStorage` идёт **без** `shot` — иначе упирается
в лимит 5 МБ.

Допустимые `kind`: `click`, `tap`, `long_tap`, `swipe`, `type`, `key`, `unlock`,
`launch_app`, `open_url`, `stop_app`, `sleep`, `screenshot`.

Соответствие типов `act()` и `kind`: `tap` → `click` при найденном узле, иначе
`tap`; `long_tap`, `swipe`, `key`, `unlock` — один в один; `text` → `type`;
`launch` → `launch_app`; `stop` → `stop_app`; `url` → `open_url`. Действие
`shell` не записывается: `adb shell` из вкладки «Устройство» это диагностика,
а не шаг сценария.

### Слипание текста

Живая клавиатура шлёт по символу. Подряд идущие шаги `type` без `clear`
сливаются в один — иначе «qwerty» это шесть строк кода. Слипание делает
`recNote` в браузере, серверу приходит уже склеенный шаг.

### Паузы

Галка «писать паузы», по умолчанию **выключена**: `ctx.click()` и так ждёт
элемент до 10 секунд. Включённая — промежуток больше 1 секунды между действиями
становится шагом `sleep`, округлённым до 0.5.

## Генерация кода

| `kind` | Строка |
|---|---|
| `click` | `ctx.click(<selector.args>)` с комментарием-меткой |
| `tap` | `ctx.tap(0.5, 0.42)` |
| `long_tap` | `ctx.long_tap(0.5, 0.42, 0.8)` |
| `swipe` | `ctx.swipe(x1, y1, x2, y2, 0.25)` |
| `type` | `ctx.type("…")`, с `clear` → `ctx.type("…", clear=True)` |
| `key` | `ctx.key("back")` |
| `unlock` | `ctx.unlock()` |
| `launch_app` | `ctx.launch_app("com.example.app")` |
| `open_url` | `ctx.open_url("https://…")` |
| `stop_app` | `ctx.stop_app("com.example.app")` |
| `sleep` | `ctx.sleep(1.5)` |
| `screenshot` | `ctx.screenshot("шаг3")` |

Шаг `click` подставляет `selector.args` как есть — `farm/ui/selectors.py` уже
формирует их валидным Python-синтаксисом с экранированием.

Результат:

```python
"""Записано конструктором фермы 26.07.2026."""
RECORDED = True
NAME = "Логин в приложении"
DESCRIPTION = "Открывает приложение и логинится"
PARAMS = {
    "login": {"label": "Логин", "default": "user@example.com"},
}


def run(ctx):
    ctx.watch_popups()
    ctx.launch_app("com.example.app")
    ctx.click(resourceId="com.example.app:id/email")   # Поле «Почта»
    ctx.type(ctx.params["login"])
```

`RECORDED = True` — маркер «свой сценарий». `farm/scenarios.py` читает атрибут
модуля, никакого разбора комментариев.

`ctx.watch_popups()` управляется галкой в форме сохранения, по умолчанию
включённой.

Строковые литералы экранирует собственная функция `codegen.literal()`.
Дублирование двух строк с `selectors._literal` осознанное: у модулей разная
ответственность — `selectors.py` строит строку для показа в интерфейсе,
`codegen.py` отвечает за валидность всего файла целиком.

Если шагов нет, кнопка сохранения неактивна — пустой `run(ctx)` не генерируется.

### Границы параметризации

Выносятся только значения шагов: `type`, `launch_app`, `open_url`, `stop_app`,
`sleep`, имя `screenshot`.

Селекторы **не параметризуются**. `ctx.click(text=ctx.params["btn"])` покрывает
редкий случай ценой структурного хранения аргументов селектора; сейчас селектор
хранится готовой строкой из `selectors.py` и подставляется без разбора.

Имя параметра проверяется по `^[a-z][a-z0-9_]{0,31}$` и на совпадение с уже
существующими.

## API

| Метод | Путь | Тело → ответ |
|---|---|---|
| `POST` | `/api/recorder/preview` | `{meta, params, steps}` → `text/plain` исходник |
| `POST` | `/api/recorder/save` | `{key, meta, params, steps, overwrite}` → `{key, path}` |
| `DELETE` | `/api/scenarios/{key}` | → `{ok: true}` |

`meta` это `{name, description, watch_popups}`. `params` это
`{имя: {label, default}}`.

Удаление живёт в `farm/api/scenarios.py`, а не в рекордере: это операция над
списком сценариев, конструктор о ней не знает. Сценарий без `RECORDED` удалить
нельзя — `403`.

### Безопасность записи файла

Три проверки, все на сервере:

1. ключ по `^[a-z][a-z0-9_]{0,47}$` — заодно отсекает `_x`, который
   `discover()` всё равно пропустил бы;
2. `path.resolve()` обязан лежать внутри `config.SCENARIOS_DIR.resolve()` —
   глушит `../../`;
3. существующий файл без `overwrite` → `409`, интерфейс спрашивает
   «Перезаписать?».

Транслитерацию кириллицы в имя файла делает форма в браузере. Это подсказка, не
защита: сервер валидирует ключ независимо от того, что пришло.

## Ошибки

| Ситуация | Поведение |
|---|---|
| нет активного устройства | `● Запись` неактивна |
| `/inspect` пуст (WebView, SurfaceView, игра) | баннер «узлы не распознаны — пишу координаты», шаги идут как `ctx.tap(x, y)` |
| `/inspect` вернул ошибку | toast, запись продолжается в режиме координат |
| устройство отвалилось в записи | запись останавливается, шаги целы, toast |
| `matches > 1` | шаг помечен `⚠`, в правке предложены альтернативы |
| клик в окно обновления дампа | шаг помечен `⚠ дамп устарел, проверь селектор` |
| перезагрузка вкладки | черновик из `localStorage`, предложение восстановить |
| коллизия имени файла | `409`, диалог «Перезаписать?» |

Тап через `input tap` отклоняется на HyperOS/MIUI без включённого тумблера
«USB-отладка (настройки безопасности)». Запись там бессмысленна — состояние не
двигается. `act()` уже показывает ошибку, отдельной обработки не добавляем.

## Тесты

`tests/` создаётся заново: папка, упомянутая в README, из репозитория пропала.
Устройство ни одному тесту не нужно.

`httpx` в окружении нет, поэтому `fastapi.testclient.TestClient` недоступен.
Тесты API вызывают функции роутера напрямую и проверяют `HTTPException.status_code` —
новую зависимость ради этого не тянем.

- **`codegen`** — каждый `kind` даёт ожидаемую строку; экранирование `"`, `\` и
  переводов строк в текстах, в `NAME` и в `DESCRIPTION`; параметр попадает в
  `PARAMS` с `default` и не оставляет литерал в теле `run`; при пустом `params`
  блок `PARAMS` не печатается.
- **интеграционный, основной** — сгенерированный текст пишется во временную
  `SCENARIOS_DIR`, `scenarios.discover()` его импортирует: `error == ""`,
  `recorded is True`, `run` вызываем. Ловит синтаксис, отступы и кавычки разом.
- **`steps`** — неизвестный `kind` отвергается; лишние ключи отбрасываются;
  `sleep` с нечисловым аргументом отвергается.
- **`save`** — ключи `../../x`, `_x`, `Ab`, пустой отвергаются; коллизия без
  `overwrite` даёт `409`, с ним перезаписывает.
- **`delete`** — сценарий без `RECORDED` даёт `403`.

Фронтенд тестами не покрывается: JS-раннера в проекте нет, добавление его —
отдельная задача.

## Вне scope v1

- обратное открытие готового `.py` в конструкторе;
- автоматическая вставка проверок `ctx.exists` / `wait_app` между шагами;
- параметризация селекторов;
- запись сразу с нескольких устройств;
- редактирование кода прямо в браузере — предпросмотр только для чтения;
- экспорт видео: это scrcpy плюс системная запись экрана.
