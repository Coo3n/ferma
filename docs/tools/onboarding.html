1. Проект за одну страницу

Ферма — это сервер на Python, который говорит с телефонами через adb, и сайт, который показывает всё человеку. Они общаются только через HTTP-запросы на адреса /api/….

android-farm/ ├── backend/ СЕРВЕР (Python) │ ├── farm/ код сервера — это Python-пакет «farm» │ │ ├── api/ адреса /api/… (по файлу на раздел) │ │ ├── devices/ реестр телефонов и очередь запусков │ │ ├── control/ действия с телефоном: нажать, ввести, открыть приложение │ │ ├── recorder/ конструктор сценариев │ │ ├── context.py ctx — то, чем пользуются сценарии │ │ ├── config.py все настройки │ │ └── server.py точка входа │ ├── scenarios/ сценарии: один .py-файл = один сценарий │ ├── guards/ правила «какое окно закрывать само» │ └── tests/ тесты (телефон не нужен) ├── frontend/ САЙТ (HTML + CSS + JS, без сборки) │ ├── index.html разметка всех разделов │ ├── design/tokens.css цвета, шрифты, отступы │ ├── strings/ru.json все тексты │ ├── css/ js/ стили и логика по разделам │ └── dev_server.py запуск сайта отдельно от сервера ├── data/ ваши данные: аккаунты, имена телефонов, логи (не в git) ├── docs/ документация └── run.sh запустить всё одной командой
Главное правилоВызовы идут только сверху вниз: сайт → API → сервисы → control/ → телефон. Нижний слой никогда не знает о верхнем. Поэтому любой кусок можно понять и проверить отдельно.
Сайт (браузер) │ fetch('/api/devices/R58N1004/action', {type: 'tap', x: .5, y: .5}) ▼ api/screen.py роутер: проверил запрос → вызвал функцию ▼ control/input.py tap(): перевёл доли экрана в пиксели ▼ adb.py adb -s R58N1004 shell input tap 540 1200 ▼ 📱 телефон

4. Путь одного нажатия: «Запустить сценарий»

  1. Сайт. Кнопка в index.html зовёт openRunDialog() (rundialog.js). Человек выбирает сценарий и телефоны, жмёт «Запустить» — уходит запрос: 
    post('/api/run', {scenario: 'warmup_vk', serials: ['R58N1001', 'R58N1002'], params: {minutes: 10}})
  2. API. api/scenarios.py принимает запрос и отдаёт работу очереди: 
    @router.post("/api/run")
def run_scenario(payload: dict = Body(...)):
    key = payload.get("scenario")
    serials = payload.get("serials") or []
    if not key:
        raise HTTPException(400, "не указан сценарий")   # ошибка уйдёт на сайт тостом
    jobs = runner.submit(key, serials, payload.get("params"), ...)
  3. Очередь. devices/runner.py кладёт по задаче на каждый телефон. У каждого телефона свой поток: телефоны работают параллельно, но на одном телефоне задачи идут по очереди.
  4. Сценарий. Поток создаёт ctx (context.py) и вызывает run(ctx) из файла сценария.
  5. Действия. ctx.click(text="Войти") → resolve.py находит кнопку → control/input.py → adb → телефон.
  6. Если что-то не так — стражи закрывают известные окна; если не помогло, задача встаёт в статус ждёт, сайт показывает «Показать, как быть», браузер пищит.
  7. Сайт видит прогресс — app.js раз в 2 секунды спрашивает GET /api/jobs и перерисовывает «Запуски».

5. Python за 20 минут — на коде этого проекта

Модули и импорт

Каждый .py-файл — модуль, папка с __init__.py — пакет. farm/control/input.py импортируется как farm.control.input. Точка в начале — «из этого же пакета».

from .. import adb, config          # подняться на уровень вверх (farm) и взять adb.py, config.py
from ..devices import registry       # farm/devices/registry.py

Переменные, списки, словари

serials = ["R58N1001", "R58N1002"]          # список
payload = {"type": "tap", "x": 0.5}          # словарь (как JSON)
payload["x"]                                 # 0.5
payload.get("y", 0)                          # 0 — если ключа нет, без ошибки
online = [d for d in devices if d.online]    # «списковое включение»: отфильтровать
name = f"Phone {i + 1}"                      # f-строка: подстановка в текст

Функции и типы

def tap(serial: str, x: float, y: float) -> None:   # подсказки типов: что принимает/возвращает
    ax, ay = to_pixels(serial, x, y)                 # функция вернула два значения
    if via_u2(serial, lambda d: d.click(ax, ay)):    # lambda — короткая безымянная функция
        return
    adb.shell(serial, ["input", "tap", str(ax), str(ay)])

Классы и dataclass

@dataclass — класс-«анкета»: перечисляете поля, Python сам пишет конструктор.

@dataclass
class Device:
    serial: str
    state: str = "offline"
    battery: int | None = None          # число или «нет данных»
    tags: list[str] = field(default_factory=list)

    @property                           # вычисляемое поле: device.online без скобок
    def online(self) -> bool:
        return self.state == "device"

try:
    png = adb.exec_out(serial, ["screencap", "-p"])

with и блокировки

Телефоны обслуживаются параллельными потоками; чтобы два потока не испортили общий словарь, его трогают под замком:

with _records_lock:            # внутри блока — только один поток
    _records[serial] = {...}

6. FastAPI: как устроен API

router = APIRouter(prefix="/api/devices")       # общий префикс для файла

@router.post("/{serial}/action")               # {serial} попадает в аргумент
def action(serial: str, payload: dict = Body(...)):   # тело запроса — словарь
    handler = ACTIONS.get(payload.get("type"))
    if handler is None:
        raise HTTPException(400, "неизвестное действие")   # 400 — ошибка запроса
    return handler(serial, payload) or {"ok": True}       # словарь → JSON

Новый файл роутера подключается одной строкой в farm/api/__init__.py: router.include_router(новый.router).

7. Сценарии и ctx

Сценарий — файл в backend/scenarios/ с функцией run(ctx). Записанные конструктором сценарии — такие же файлы, их можно читать и править.

NAME = "Прогрев VK"
PARAMS = {"minutes": {"label": "Минут на телефон", "type": "number", "default": 10}}

def run(ctx):
    ctx.launch_app("com.vkontakte.android", stop_first=True)
    ctx.click(text="Лента", timeout=10)
    for _ in range(20):
        ctx.swipe(0.5, 0.75, 0.5, 0.3)
        ctx.sleep(3)
        ctx.on_track("com.vkontakte.android")    # сторож: своё ли приложение, листается ли
    ctx.home()
КомандаЧто делает
ctx.click(text=…) / ctx.click_target(sel, text, img, at)нажать; второй ищет в несколько слоёв
ctx.type("текст") · ctx.key("back")ввести текст, нажать клавишу
ctx.tap(x, y) · ctx.swipe(…)нажатие и свайп в долях экрана (0…1)
ctx.launch_app(pkg) · ctx.open_url(url)открыть приложение, ссылку
ctx.expect_screen(name, any=[…])«я обязан быть на этом экране» — иначе спросит человека
ctx.which_screen({…})развилка: какой из экранов сейчас
ctx.on_track(pkg)сторож долгих циклов
ctx.account("vk")логин и пароль аккаунта этого телефона
ctx.run("block")выполнить другой сценарий как блок
ctx.params["minutes"]параметры из окна запуска
ctx.log("…") · ctx.screenshot()строка в журнал, снимок в артефакты
Не храните пароли в сценарияхИспользуйте ctx.account("vk")["password"] — пароль лежит в data/accounts.json, а не в коде, который видят все.

8. JavaScript сайта: пять вещей

  1. S — всё состояние: S.devices, S.jobs, S.active (открытый телефон).
  2. api(path) / post(path, body) — запрос к серверу; ошибка уже по-русски.
  3. toast(t('ключ'), 'ok') — сообщение внизу экрана.
  4. onclick="функция()" в разметке — так кнопки вызывают код.
  5. Опросы в app.js обновляют S и перерисовывают разделы сами — руками перерисовывать почти никогда не нужно.

9. Добавляем фичу: три примера

Пример 1. Кнопка «Без звука» в пульте

  1. Сервер, backend/farm/api/screen.py — функция и строка в ACTIONS: 
    def _mute(serial, p):
    adb.shell(serial, "media volume --stream 3 --set 0", timeout=SHELL_TIMEOUT)

ACTIONS = {
    ...
    "mute": _mute,
}
  2. Текст, frontend/strings/ru.json: "pult.bez_zvuka": "Без звука",
  3. Кнопка, frontend/index.html, внутри <div class="pult-keys">: 
    <button class="key" data-live onclick="act({type:'mute'})" data-t="pult.bez_zvuka">
    <svg class="ic"><use href="#i-volume-low"/></svg>Без звука</button>
  4. Бонус: то же действие сразу работает на многих телефонах: bulkAction({type: 'mute'}, 'Без звука').

Пример 2. Новый адрес API

# backend/farm/api/devices.py
@router.get("/groups/count")
def groups_count():
    counts = {}
    for d in registry.all():
        name = d.group or "без группы"
        counts[name] = counts.get(name, 0) + 1
    return counts                      # GET /api/devices/groups/count → {"VK-10": 12, ...}

10. Тесты

Тесты лежат в backend/tests/, телефон им не нужен: всё, что ходит в adb, подменяется через monkeypatch.

def test_поворот(phone):                       # phone — подготовка из фикстуры
    res = api_screen.action("A", {"type": "rotate"})
    assert res["landscape"] is True             # assert: «должно быть так», иначе тест красный
    assert "settings put system user_rotation 1" in phone
cd backend
../.venv/bin/python -m pytest -q                      # все тесты (~30 секунд)
../.venv/bin/python -m pytest -q tests/test_watch.py  # один файл
../.venv/bin/python -m pytest -q -k поворот           # по части имени
ПривычкаСделали фичу — напишите один тест по образцу соседнего файла и прогоните все тесты перед коммитом.
