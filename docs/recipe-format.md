# Формат сценария (рецепт)

Конструктор хранит сценарий как **рецепт** — JSON со списком шагов. Из рецепта
сервер собирает `.py`-файл в `backend/scenarios/`. Этот же формат подходит
внешнему помощнику, например ИИ, который составляет или правит сценарии:
он пишет рецепт, сервер его проверяет и сохраняет.

Список видов шагов, полей и ограничений можно получить с работающей фермы:
`GET /api/recorder/schema`. Этот документ объясняет, что они значат.

## Как отправить

| Запрос | Что делает |
|---|---|
| `POST /api/recorder/preview` | возвращает код `.py` (текстом), ничего не сохраняет |
| `POST /api/recorder/validate` | ошибки и предупреждения по шагам (`serial` проверит, установлены ли нужные приложения) |
| `POST /api/recorder/save` | сохраняет сценарий (`key` — имя файла, `overwrite: true` — заменить существующий) |
| `GET /api/recorder/recipe/{key}` | рецепт уже сохранённого сценария, чтобы его поправить |

Тело запроса:

```json
{
  "key": "vk_lenta",
  "meta": {"name": "Лента ВК", "description": "листаем и иногда лайкаем",
           "watch_popups": true, "human": true},
  "params": {},
  "steps": [ ... ]
}
```

Если что-то не так, ответ — `400` с понятным текстом на русском
(«блок выходит за границу внешнего блока»). Помощник может показать его
человеку или исправить рецепт сам.

## Шаг

```json
{"kind": "swipe", "args": {"x1": 0.5, "y1": 0.8, "x2": 0.5, "y2": 0.3}, "note": "листаем"}
```

- `kind` — вид шага (`click`, `tap`, `swipe`, `type`, `key`, `launch_app`, `sleep`, `expect`, `branch`, …).
- `args` — аргументы. Координаты указываются долями экрана от 0 до 1.
- `note` — подпись для человека, необязательна.
- `optional: true` — если шаг не удался, пропустить его. `retries: N` — повторить при неудаче (не больше 5).

### Нажать на элемент — `click`

```json
{"kind": "click",
 "selector": {"call": "click", "args": "description=\"Нравится\"",
              "fallbacks": ["resourceIdMatches=\".*/like_button$\"", "text=\"Нравится\""]}}
```

`args` — способ найти элемент на экране, записанный как `ключ="значение"`
(`text`, `textContains`, `description`, `resourceId`, `resourceIdMatches`,
`instance` — номер среди совпавших).
`fallbacks` — запасные способы, «или так» (до 3). Шаг нажмёт первое, что найдёт.

Одинаковые элементы (лайки в ленте с одним id и подписью): «нужен вот этот»
записывается номером среди похожих — `instance` считается с нуля в порядке
дерева экрана, `resourceId="app:id/like", instance=1` — второй лайк. Номер
хрупкий: лента сдвинется — попадёт в другой пост; поэтому панель ставит его
только когда устойчивого однозначного признака нет.

Устойчивее номера — сказать, ГДЕ искать (необязательные поля, не больше
одного на шаг; старые рецепты без них работают как раньше):

```json
{"kind": "click",
 "selector": {"call": "click", "args": "resourceId=\"app:id/like\"",
              "fallbacks": ["description=\"Нравится\""]},
 "near": "text=\"Иван Петров\""}
```

- `within` — «внутри»: селектор контейнера; цель ищется только среди его
  потомков (`instance` считается среди них). Пример:
  `"within": "resourceId=\"app:id/stories\""`.
- `near` — «рядом с»: селектор ориентира; из всех совпавших нажимается
  ближайший к нему — сначала тот, у кого общий с ориентиром предок глубже
  (та же карточка поста), при равенстве — ближе по экрану.

Строка той же грамматики, что `args`, но ключи только `text`, `textContains`,
`textStartsWith`, `description`, `descriptionContains`,
`descriptionStartsWith`, `resourceId`, `className` (до 3, значение до 200
символов). Меняющаяся надпись (время, счётчик, `@ник`) ориентиром быть не
может — шаг не сохранится. Место поиска действует на основной способ и на
каждый из `fallbacks`; ключи цели при этом — из тех, что ферма проверяет по
дереву экрана (`text*`, `description*`, `resourceId`, `resourceIdMatches`,
`className`, `packageName`, `clickable`, `instance`). В коде это хвост вызова:
`ctx.click(resourceId="app:id/like", near=dict(text="Иван Петров"))`, так же у
`ctx.click_any(...)` и `ctx.click_target(...)`. Нет контейнера или ориентира —
шаг останавливается с понятной причиной («не найден ориентир …»). Ограничения:
к элементу с местом поиска экран сам не прокручивается; запасные слои
`texts`/`crop`/`point` место поиска не учитывают.

Панель предлагает место поиска сама, когда похожих несколько: «внутри: …»
или «рядом с: «…»» с пометкой «✓ один на экране»; ориентир можно и указать
пальцем на экране телефона.

Не стоит искать по тексту, который меняется сам (время `12:45`, счётчик
`125`, `5 мин назад`, `@ник`): завтра он будет другим. Панель такие варианты
помечает «текст меняется», ставит ниже и не берёт в запасные сама.

У записанного шага есть ещё запасные слои: `texts` (поиск по надписи и OCR),
`crop` (картинка элемента, порог совпадения 0.85) и `point` (место нажатия,
доли экрана). Если картинка нашлась в нескольких местах, нажимается
ближайшее к `point`.

### Проверка экрана — `expect`

```json
{"kind": "expect", "args": {"name": "лента"}, "any": ["text=\"Новости\""]}
```

Её ставят только там, где экран действительно важен. Экраны приложений
меняются, и лишние проверки роняют рабочий сценарий.

## Блоки

Блок — шаг-рамка. `args.span` — сколько следующих шагов входит в блок.
Блоки вкладываются друг в друга, не глубже 3 уровней. Вложенный блок
не может выходить за конец внешнего.

| Блок | Аргументы | Что делает |
|---|---|---|
| `loop` | `times` **или** `minutes`, `pause_min`/`pause_max` (сек), `watch` | крутит шаги внутри по кругу |
| `chance` | `percent` (1–100) | выполняет шаги внутри иногда, с заданным шансом |
| `until` | `any` (что искать), `tries` (до 200), `on_fail`: `skip` / `fail` / `ask` | крутит шаги, пока на экране не появится цель |
| `if_seen` | `any` (что искать), `negate` (true — «если НЕТ»), `timeout` (сек, до 60, по умолчанию 3) | выполняет шаги внутри, только если цель есть (или нет). Пара «есть» + «нет» = «иначе» |

Шаги логики (не блоки, `span` не нужен):

| Шаг | Аргументы | Что делает |
|---|---|---|
| `break` | — | выйти из ближайшего `loop`/`until`; вне них — ошибка |
| `finish` | `result`: `ok` / `fail`, `reason` | закончить сценарий успешно или с ошибкой. Внутри `call` заканчивает только вызванный сценарий |
| `call` | `scenario` (ключ сохранённого сценария) | выполнить другой сценарий как шаг |

Если элемент может не найтись: `{"kind": "if_seen", "args": {"span": 1}, "any": [...]}` + клик внутри,
и рядом `if_seen` с `negate: true` — запасной путь.

Пример: 10 минут листать ленту и в 15 % кругов ставить лайк, потом листать,
пока не появится «Подписаться» (не нашёл за 5 кругов — спросить человека):

```json
[
  {"kind": "launch_app", "args": {"package": "com.vkontakte.android"}},
  {"kind": "loop", "args": {"span": 3, "minutes": 10, "pause_min": 1, "pause_max": 3}},
  {"kind": "swipe", "args": {"x1": 0.5, "y1": 0.8, "x2": 0.5, "y2": 0.3}},
  {"kind": "chance", "args": {"span": 1, "percent": 15}},
  {"kind": "click", "selector": {"call": "click", "args": "description=\"Нравится\"",
                                 "fallbacks": ["resourceIdMatches=\".*/like_button$\""]}},
  {"kind": "until", "args": {"span": 1, "tries": 5, "on_fail": "ask"},
   "any": ["text=\"Подписаться\""]},
  {"kind": "swipe", "args": {"x1": 0.5, "y1": 0.8, "x2": 0.5, "y2": 0.3}}
]
```

`span` у `loop` равен 3, потому что внутри него три шага: свайп, блок
`chance` и клик, который входит в `chance`.

Сервер соберёт из этого:

```python
ctx.launch_app("com.vkontakte.android")
for _ in ctx.loop(minutes=10, pause=(1, 3)):
    ctx.swipe(0.5, 0.8, 0.5, 0.3, 0.25)
    if ctx.chance(15):
        ctx.click_any(dict(description="Нравится"), dict(resourceIdMatches=".*/like_button$"))
for _ in ctx.until_found([dict(text="Подписаться")], tries=5, on_fail="ask"):
    ctx.swipe(0.5, 0.8, 0.5, 0.3, 0.25)
```

## Чего помощнику не делать

- Не писать `.py` руками в обход рецепта: такой сценарий не откроется в конструкторе.
- Не вписывать логины и пароли. Шаг `type` с `args.account` (`vk`, `inst`, `tiktok`, `tg`)
  и `args.field` (`login`, `password`, `phone`) берёт их из раздела «Аккаунты».
- Не нажимать по координатам, если элемент можно найти по тексту или id.
